_NAV_GROUPS = (

기존 `_MAIN_NAV_OPTIONS` 주석에만 있던 묶음을 실제 자료구조로 승격했다.
**평탄화하면 `_MAIN_NAV_OPTIONS` 와 순서까지 같아야 한다** — 어긋나면 탭이
사라지거나 중복된다. `diag_startup [1]` 이 이를 강제한다.

`_MAIN_NAV_OPTIONS` 는 그대로 둔다. `_NAV_GROUPS` 에서 파생시키면 컴프리헨션이
되어 `diag_startup` 의 AST 원소 검사(`ast.Name` 여부)가 다시 깨진다. 두 곳을
유지하되 **드리프트를 진단으로 막는** 쪽을 택했다.

#### (2) 사이드바 렌더 교체

```python
for _gname, _gitems in _nav_groups:
    with st.sidebar.expander(_gname, expanded=(_cur_nav in _gitems)):
        for _t in _gitems:
            st.button(_t, key=f"_nav_btn_{_t}", use_container_width=True,

```

관리자 항목은 런타임에 마지막 그룹에 붙는다
(`_nav_groups[-1][1].append(_NAV_ADMIN_APPROVAL)`).

## 2. 설계 근거

### `st.radio` 를 버리고 버튼을 쓴 이유

`st.radio` 는 그룹 헤더를 지원하지 않는다. 검토한 대안:

| 안 | 기각 사유 |
|---|---|
| 라디오에 `── 분석 도구 ──` 구분선 항목 삽입 | 선택되면 되돌려야 하고, 그 과정에서 깜빡임이 보인다 |
| 그룹마다 독립 라디오 5개 | 상호 배타를 수동으로 관리해야 한다 |
| `st.selectbox` | Streamlit 은 optgroup 을 지원하지 않는다 |
| **expander + 버튼** | 채택 |

### expander 여닫기가 rerun 을 일으키지 않는다

이 점이 설계의 전제다. expander 토글은 프런트엔드 동작이므로,
`expanded=(_cur_nav in _gitems)` 를 매 렌더 넘겨도 **사용자가 다른 그룹을
열어보는 것은 자유롭다.** rerun 이 걸리는 시점은 탭 버튼을 누를 때뿐이고,
그때 새 활성 그룹이 펼쳐진다.

만약 토글이 rerun 을 일으켰다면 이 설계는 성립하지 않는다 — 다른 그룹을 여는
순간 다시 닫혀 이동 자체가 불가능해진다.

### 위젯 키 제거가 부수적으로 안전하다

`main_sidebar_nav` 는 라디오의 위젯 키였다. 본문 8곳이 이 키에 직접 대입하는데
(`정밀검사로 이동` 버튼 등), 위젯 인스턴스화 이후 대입은 Streamlit 이 예외를
던진다. 지금까지는 **전부 `on_click` 콜백 안에 있어서** 성립했다.

버튼으로 바꾸면 이 키는 평범한 세션 값이 된다. 콜백 밖에서 대입해도 안전해져
제약이 하나 사라진다.

### 라벨을 줄이지 않은 이유

`🔬 [3단계] 개별 종목 정밀 검사` 는 사이드바 버튼으로 길다. 그룹이 생겼으니
`[3단계]` 접두는 중복이기도 하다. 다만 라벨 문자열은 곧 분기 키이고,
`_tab_hint` 의 세션 캐시 키이기도 하다. **이번 패스에서 같이 바꾸면 문제가
생겼을 때 그룹화 탓인지 라벨 탓인지 갈라내기 어렵다.** 별도 건으로 남긴다.

## 5. 남은 한계 · 후속

- **그룹 간 이동에 클릭이 1회 늘어난다.** 다른 그룹을 펼친 뒤 탭을 눌러야 한다.
  자주 오가는 조합(정밀 검사 ↔ 매도 레이더)이 서로 다른 그룹이라 체감될 수 있다.
  걸리면 그룹 구성을 조정하거나 캡션+버튼(그룹 항상 펼침)으로 되돌릴 수 있다.
- **버튼이 라디오보다 세로로 두껍다.** 그룹이 접혀 있어 총 높이는 줄지만,
  활성 그룹 안에서는 항목당 높이가 늘어난다.
- 라벨 축약(`[n단계]` 접두 제거)은 미실시 — 별도 건.
- `_MAIN_NAV_OPTIONS` 와 `_NAV_GROUPS` 가 **두 곳에 같은 정보를 담는다.**
  진단이 드리프트를 막지만, 탭 추가 시 두 곳을 모두 고쳐야 한다.
