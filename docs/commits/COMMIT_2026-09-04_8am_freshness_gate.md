DRG 예측 뒤, `📋 실행 로그 요약` 앞에 단계 1개 추가. 기존 8개 단계는 무변경.

```yaml
      - name: 🔁 락스텝 관문 — 사본 지문 + 모듈 간 정합성
        if: always()
        run: python check_freshness.py .
```

**설계 판단 세 가지와 근거**

| 판단 | 선택 | 근거 |
|---|---|---|
| 위치 | **맨 뒤** | 이 검사는 막을 수 있는 게 없다. 8AM 시점엔 배포가 이미 끝난 일이라 오늘 이메일을 막아도 되돌려지지 않는다. 목적은 **통보**다. 그날 산출물(내러티브·DRG)은 무조건 나간다 |
| 실패 처리 | **하드 실패** | `continue-on-error: true` 면 잡이 초록이라 아무도 안 본다 — 지금(수동 전용)과 실질적으로 같아진다. 빨간불이 통보 채널이다 |
| 조건 | **`if: always()`** | 앞 단계가 죽어도 돈다. `run_narrative` 가 크래시했을 때 "왜 죽었는지"를 같은 실행 안에서 준다 |

**앞에 두지 않은 이유** — 검사 범위가 코어·러너 전체라, 토요일에만 도는
`run_hidden_alpha` 의 불일치로 평일 아침 내러티브가 막힌다. 폭발 반경이 안 맞는다.

**빨간불이 자주 뜨지 않는 이유** — 진단·일회성 스크립트(`diag_*` · `check_*`)의
불일치는 경고로만 나가고 exit 코드에 반영되지 않는다. 실패는 `app.py` ·
`*_core.py` · `run_*` · `refresh_*` 불일치일 때만 난다.

**비용** — 의존성 불필요(`ast`/`os`/`sys` 만 사용, 프로젝트 모듈을 임포트하지
않는다). 실측 0.03초. 30분 타임아웃에 영향 없음.
