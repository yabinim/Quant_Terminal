## 1. 무엇이 잘못돼 있었나

`run_signal_backtest._pos_label_at` 이 `rc.integrated_sell_verdict` 를 호출하면서
`gap_ma200_pct` 를 넘기지 않았다. 이 인자가 없으면 함수는 200일선 이탈에
**일괄 4.0점**을 주는 보수적 폴백으로 간다.

```python
if above_ma200 is False:
    if gap_ma200_pct is not None and pd.notna(gap_ma200_pct):
        score += 2.0 + 2.0 * min(1.0, abs(gap) / 8.0)   # 3E 램프 (프로덕션)
    else:
        score += 4.0                                     # 폴백 (백테스트)
```

4.0 은 곧 `score >= 4` → **🔴 청산 문턱**이다.

### 갈림의 크기 (실측)

2026-08-27 `diag_sell_verdict` [4] 블록, 200일선 아래 21종목:

| 이격 구간 | 종목 | 비율 | 프로덕션 | 백테스트 |
|---|---|---|---|---|
| 0 ~ −4% | 13 | **61.9%** | 2.0~3.0 | **4.0** |
| −4 ~ −8% | 1 | 4.8% | 3.0~4.0 | **4.0** |
| −8% 초과 (포화) | 7 | 33.3% | 4.0 | 4.0 ✅ |

**백테스트가 프로덕션보다 체계적으로 매도에 적극적이었고, 그 격차가 200일선 아래
종목의 3분의 2에 걸렸다.** 포화 구간에서만 두 경로가 일치한다.

> 이 단면은 시장 국면에 따라 통째로 이동한다. 비율 자체를 상수로 받아들이지 말 것.

### 왜 몇 달간 안 보였나

`_pos_label_at` 의 독스트링에 이렇게 적혀 있었다:

```
"""사전계산 입력 + 진입 이후 고점 → integrated_sell_verdict (SSOT 그대로)."""
```

**"SSOT 그대로" 가 거짓이었다.** 주석은 계약을 주장할 뿐 강제하지 않는다. 인자를
빼먹어도 예외가 안 나고, 타입 오류도 없고, 로그도 안 남는다. 정상 실행되고
정상적으로 라벨을 반환한다. 다른 것은 점수뿐이다.

## 4. 설계 근거 · 기각한 대안

### 4-1. gap 을 `_position_features` 에서 미리 계산 — **기각**

처음에 이 안(선택 B)을 추천했다가 **코드로 옮기면서 철회했다.**

미리 계산하면 분자(가격)가 `_pos_label_at` 의 인자 `price` 에서, 분모(ma200)가
feats 배열에서 — **서로 다른 경로로** 온다. 오늘은 호출부가 `float(close[i])` 를
넘기고 `close` 와 `c` 가 같은 `h["Close"]` 라 값이 일치한다. **오늘은 맞다.**
하지만 나중에 누가 다른 price 를 넘기는 순간 `dd` 와 `gap` 이 조용히 갈라진다.

이번 세션이 잡고 있는 결함들이 전부 그 모양이다 — §2-3(같은 종목의 then/now 가
서로 다른 고점 창), §2-5(진단 복제본이 SSOT 와 갈라짐), §3-1(호출부가 인자 누락).
셋 다 "오늘은 맞다" 였다.

**추천 근거였던 "벡터화 원칙"도 약했다.** 그 독스트링이 말하는 무거운 것은
RSI·MACD·롤링 이평이지 나눗셈 하나가 아니다. 같은 루프가 매 iteration 마다
`analyze_fn(slice_)` 로 커져가는 슬라이스 전체에 롤링 재계산을 건다 — 45분
실행 시간은 거기서 나온다. 그 옆에서 나눗셈 한 번은 측정되지 않는다.

### 4-2. A4 를 `diag_regime_window` 에 두기 — **기각**

`diag_regime_window` 는 `regime_core` 락스텝 짝이지만, A4 의 검사 대상은
**호출부**다. `diag_fmp_ssot` 의 A 그룹은 정의부터가 *"저장소 전역 · 대상 무관 ·
영구"* 이고 A2 가 크로스모듈 호출 계약이라 성격이 정확히 같다.

그 파일의 존재 이유 자체가 *"공유 함수의 계약이 바뀌었는데 호출부를 안 고쳤다"* 이고,
이번 건이 정확히 그 모양이다.

### 4-3. `trailing_stop_pct` 도 같이 넘기기 — **불필요**

`_pos_label_at` 이 이 인자도 안 넘긴다는 것을 발견하고 조사했으나,
`app.py` · `run_watchlist_alerts.py` · `accounts_core.py` 어디에도 이 인자를
넘기는 곳이 **0곳**이었다. 프로덕션도 기본값 15.0 을 쓴다.
**백테스트의 생략은 프로덕션과 동일한 동작**이므로 드리프트가 아니다.

기준선 run 과 수정 후 run 은 `Run_Date` · `Universe_Hash` · `Mode` · `Segment` ·
`Year` 가 **전부 같아서 시트만 보고는 영구히 구분되지 않는다.**

**지금 할 일**: 기준선 Actions run 의 **URL 을 보관**할 것. 로그에 요약이 남아 있다.
append-only 라 시트에서는 뒤에 오는 행이 수정 후 행이지만, 그 순서 정보는
문서화되지 않으면 다음 세션에 소실된다.

**후속 과제(이번 세션 범위 밖)**: `_RT_COLS` 에 `Verdict_Rule` 열 추가.
`Entry_Rule` 과 정확히 같은 목적이다. 스키마 변경이라 신호 변경과 같은 커밋에
묶지 않았다.

### [6] 롤백

두 파일을 이전 버전(`run_signal_backtest.py` 1,495 · `diag_fmp_ssot.py` 773)으로
되돌리면 끝. **Streamlit 재부팅 불필요.**

**데이터 손실 없음** — 백테스트는 append-only이고 기존 행을 건드리지 않는다.
다만 §[5] 때문에 **수정 후 run 의 행이 시트에 남아 기준선 행과 섞인다.**
롤백한다면 그 행들을 수동으로 지우거나, 지우지 않는다면 어느 행이 어느
규칙이었는지 별도로 기록해 둘 것.
