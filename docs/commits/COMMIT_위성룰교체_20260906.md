# 위성 랭킹 룰 교체 — blend → 12-0 (2026-09-06)

## 무엇을 바꿨나

HSA 위성 슬리브의 섹터 챔피언 랭킹 점수식을 교체했다.

| | 이전 | 이후 |
|---|---|---|
| 점수 | `1M×0.40 + 3M×0.40 + 6M×0.20` | **12개월 수익률 (12-0)** |
| 소요 이력 | 127봉 (리터럴) | **253봉 (MOM_RULES 파생)** |
| 참고 열 | 없음 | **12-1 점수·Top5 병기 (표시 전용)** |

Top5 균등 배분, 주간 swap, SPY 200MA 시장 필터는 **변경 없다.**

## 근거

`diag_momentum_rule_compare` 워크포워드 6창(2022-09 ~ 2026-09), 사전 커밋 임계:

- **T1** 12-1 vs 현행 — 샤프 6/6창 우위 (임계 4/6) → 통과
- **T2** 12-0 vs 현행 — 5/6창 우위 → 통과
- **T3** Top3 vs Top5 — 2/6 + MDD 악화 → 미달, Top5 유지 (종결)
- **T4** 차등 vs 균등 — 최고 4/6 → 미달, 균등 유지 (종결)
- **T7** 위험조정 12-0 vs 12-0 — 2/6 (임계 5/6) → 미달 (종결).
  반증열(위험조정이 12-1 에도 듣는가) 1/6 로 방향 일치 = 구간 잡음 아님

12-1 과 12-0 중 12-0 을 택한 이유: top5_eq 6창 평균이 전 항목 우세
(수익 30.3/25.6 · MDD -16.2/-16.8 · 샤프 1.17/1.00 · 회전 7.3x/8.2x)이고,
FF48 산업 1975~2024 문헌이 산업 포트폴리오에서 12-0 을 지지한다.
12-1 의 6/6 우위는 창6의 샤프 0.01 차이에 의존한다.

⚠️ QQQ/VOO/MTUM 대비 우위는 **판정하지 않았다**(후보 풀 선택 편향). 다만
현행 blend 15.4% 가 MTUM 23.0% 에 진 것은 한 방향 추론으로 유효하다 —
위로 부풀린 숫자가 그래도 졌기 때문이다.

## 같이 고친 버그

이전 커밋에서 `_trailing_return(s, 126)` 을 `mom_components(s)` 로 바꾸면서
`diag_hist_window_consumers` 의 R1b 가 깨져 있었다(역산 1봉 vs 선언 127봉).
역산기가 모듈 상수와 계산된 첨자(`a[n-1-skip-back]`)를 따라가지 못한다.
해당 워크플로가 수동 전용이라 아직 안 터졌을 뿐이다.

역산기를 고치는 대신 **정책 소유자에서 직접 읽는 [S] 군**을 신설했다.
`run_hidden_alpha` 가 `rc.REQUIRED_BARS` 로 [H] 군에 간 것과 같은 처리다.

## 드리프트 방지 구조

```python
SATELLITE_RANK_RULE = "mom12_0"
SATELLITE_BARS = MOM_RULES[SATELLITE_RANK_RULE][1]   # → 253
```

룰을 바꾸면 깊이가 따라온다. 예전처럼 `bars=127` 을 손으로 적어두면
룰만 12-0 으로 바꿨을 때 후보 대부분이 이력 부족으로 **조용히** 탈락하고
오래된 ETF 만 살아남는다. 그 실패는 로그를 남기지 않는다.

`[S]` 군이 지키는 것 (11게이트):
- S1 호출부가 정책을 이름으로 참조하는가 (리터럴 복사 금지)
- S2 `SATELLITE_BARS` 가 `MOM_RULES` 파생인가 (리터럴로 굳지 않았는가)
- S3 선언 필요봉수 == 점수함수의 **실측** 최소 봉수 (5룰 전부, 양방향)
- S4 라이브 룰이 존재하는가 · 참고 룰과 다른가 · `mom_score` 에 문자열
  리터럴이 박히지 않았는가 (박히면 상수를 바꿔도 점수가 안 바뀐다)
- S5 이력 가드가 조회와 같은 이름을 쓰는가 (가드만 리터럴이면 스킵 사유가
  '히스토리 부족'이 아니라 '점수 산출 실패'로 엉뚱하게 찍힌다)

## 12-1 병기 (표시 전용)

12-0 채택 근거는 4년 백테스트다. 그 선택이 옳았는지는 앞으로의 실제
데이터로만 알 수 있고, 그러려면 "12-1 이었으면 무엇을 들었을까"가 매주
남아 있어야 한다. 지금 안 쌓으면 1년 뒤에도 똑같이 모른다.

- 각 행에 `<12-1 +NN.N>` 병기
- 표 아래 "12-1 이었다면 Top5: … (현재 Top5와 N/5 일치)"

  순서 변화만 알 뿐 '다른 종목을 들었을까'는 알 수 없다
- **추가 API 호출 0** (같은 종가 배열 재사용)
