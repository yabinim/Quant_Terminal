# docs(satellite): 위성 슬리브 마감 문서 + 앱 렌더 + 리마인더 2건 (①  가동)

A/B 분할(2026-09-07 개시)로 확정된 위성 슬리브 규칙이 어디에도 적혀 있지 않았다.
숫자는 전부 머리에만 있었고, 종료·축소 트리거 ①②③ 중 무엇도 실제로 울리지 않았다.
이 커밋으로 **①(전제 붕괴)이 실제 작동**한다. ②③ 은 여전히 미구축이며 문서에 그렇게 명시했다.

## 파일별 변경

### 1. `SATELLITE_MANDATE.md` — 신규 (루트, 101줄)

위성 슬리브 규칙의 **유일한 출처**. 사람이 읽는 문서인 동시에 앱이 그대로 렌더하는 원본.

| 절 | 내용 |
|---|---|
| §1 | 확정 숫자 — 총액 **1/3** (A반 1/6 · B반 1/6), 각 반 5종목 등가중, **월간** 리밸런싱, 두 장부 사이 리밸런싱 금지, 개시일 2026-09-07 |
| §2 | 랭킹 규칙 — A반 `mom12_0` 253봉 / B반 `blend`. SSOT `fmp_extras.compute_satellite_top10` |
| §3 | 시장 필터 — SPY < 200일선 시 신규 매수 중단 (기존 합의 유지) |
| §4 | 종료·축소 트리거 3종. ① 전제 붕괴(6개월 · T2 4/6창 · 3회 연속 미달 시 종료 검토) ② 실행 실패 ③ 자본 손상(**합산** −30% → 1/3→1/6) |
| §5 | 판정에서 **제외**하는 것 — 개별 종목 손익 · 6개월 미만 성과 · QQQ/VOO/MTUM 대비 · 백테스트 수익률 대비 |
| §6 | 지금 실제로 작동하는 것 — ①✅ ②❌ ③❌ 를 정직하게 표기 |
| §7 | 개정 이력 |

**설계 결정**

- **−30% 는 장부별이 아니라 슬리브 합산.** 한쪽만 자본이 줄면 그 시점 이후 A/B 비교가 전부 오염된다. 실험을 지키려면 두 장부는 항상 같이 움직여야 한다.
- **§5 를 사전에 못 박았다.** 추적오차가 연 약 17.5% 라 성과 기반 종료 기준은 통계적으로 신뢰할 수 없다(Cornell·Hsu·Nanigian, JPM 2017). ①②③ 이 전부 성과 기준이 아닌 이유다.
- **§6 을 넣은 이유.** ②③ 이 미구축인데 문서에 규칙만 적으면 "적었으니 관리된다"는 착각이 생긴다.

**코드 상수 대조 (이번 세션 실측)** — `SATELLITE_BARS` 253 · `SATELLITE_ALT_BARS` 127 · `SATELLITE_SLOTS` 5 · `RANK/ALT` = `mom12_0`/`blend`. 문서 §1·§2 와 전부 일치.

**(b) 접이식 패널** — 위성 섹션 최하단, `if _sat…/elif` **밖**

`📋 위성 슬리브 원칙 — 총액 1/3 · A반·B반 각 1/6 · −30% 시 절반 · 6개월 전제 점검`

**왜 문안을 app.py 에 복사하지 않았나:** 두 벌이 되면 반드시 갈라지고, −30% 구간에서 어느 쪽이 진짜인지 모르게 된다. md 하나만 읽으므로 구조적으로 드리프트가 불가능하다.

**왜 `if/elif` 밖인가:** Top10 계산 버튼을 누르지 않아도, 계산에 실패해도 원칙은 보여야 한다. 원칙은 매수 직전 그 자리에 있어야 의미가 있다 — 별도 문서로 두면 −30% 가 온 날 아무도 열지 않는다.

**md 부재 시:** 패널이 사라지지 않고 경고 + 핵심 숫자 요약을 띄운다. 조용히 비면 규칙이 없어진 줄 모른다.

## 남은 한계

- **②③ 은 여전히 죽어 있다.** 실행 이탈 기록(백로그 4번)과 월별 슬리브 스냅샷(백로그 3번)이 없으면 문서의 해당 조항은 의도 선언일 뿐이다. §6 에 그렇게 적어 두었다.
- **`hsa-위성-12-0` / `hsa-위성-blend` 는 코드 상수가 아니다.** 사용자가 직접 입력하는 계좌명이라 오타 검증이 없다. 오타가 나면 조용히 세 번째 장부가 생기고 A/B 집계가 깨진다.
- **문서 ↔ 코드 상수 드리프트를 막는 영구 가드가 없다.** 오늘은 손으로 대조했다. `SATELLITE_BARS`·`SATELLITE_SLOTS`·랭킹 룰 이름이 바뀌어도 md 는 조용히 낡는다.
- 패널은 `st.cache_data(ttl=3600)` 이라 md 를 고친 뒤 최대 1시간 또는 재부팅까지 옛 문안이 보인다.
