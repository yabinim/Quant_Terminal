# fix(diag): MA200 격차 원인 규명 블록 + A1 탐지기 변수 URL 추적

`diag_sell_verdict.py` 의 [0] 블록을 "배당조정 영향 표시"에서 **격차 원인 규명**으로
바꾸고 [T] 자기검증을 신설했다. 그 과정에서 `diag_fmp_ssot.py` 의 A1 탐지기가
변수에 담긴 FMP URL 을 통째로 놓치고 있는 것이 드러나 함께 고쳤다.

---

## 1. 이번 변경의 출발점 — 인수받은 전제가 틀렸다

인수인계는 "우리 NEE MA200 = 87.87 이 외부(89.77 / 91.64)보다 낮으니 배당조정이
빠진 것"이라고 진단했다. **부호가 반대다.**

배당조정(후방조정)은 과거 가격을 **낮춘다.** 따라서

```
배당조정 MA200  <  미조정 MA200
```

우리 값이 이미 미조정인데 외부가 **더 높다.** 배당조정을 도입하면 격차는
**더 벌어진다.** 이 전제로 코드를 고쳤다면 문제를 악화시켰을 것이다.

그리고 결정적으로 — **외부 두 값끼리 1.87 (2.1%) 다르다.** 같은 종목, 같은
지표인데 그렇다. 외부값은 단일 정답이 아니며 **우리를 재는 자로 쓸 수 없다.**
현재는 "우리가 틀렸다"는 증거조차 확보되지 않은 상태다.

그래서 [0] 블록의 목적을 바꿨다: 배당조정을 **도입**하는 것이 아니라
**가설을 기각하거나 채택**하고, 동시에 다른 후보(중복 날짜 · 창 길이 ·
min_periods 완화)를 같은 화면에서 가른다.

`_fmp_rows` 가 `requests.get` 을 직접 때리고 있었다. `_fmp_rows_ex(ticker,

## 4. 확정안에서 벗어난 부분 (검토 요청)

지난 세션 확정본을 그대로 재현하지 않은 곳이 **한 군데** 있다.

확정본의 min_periods 경고는 게이트가 `rc.W52_BARS`(252)인데 메시지는
"200봉 평균이 아니다"라고 단정했다. **봉이 200~251개면 그 문장은 거짓이다** —
`min_p=150` 이어도 봉이 200개 있으면 진짜 200봉 평균이다. 진단이 거짓 문장을
출력하면 나중에 그 출력을 읽는 사람이 잘못된 결론을 낸다.

3분기로 나눴다:

- 봉 < 150 → 프로덕션도 NaN
- 150 ≤ 봉 < 200 → "200봉 평균이 아니다" (참)
- 200 ≤ 봉 < 252 → "ma200 은 정상(200봉 충족)이나 52주 창이 짧다" (참)

**T3c(220봉)** 케이스와 뮤테이션 **M-h** 로 고정했다. 되돌리려면 T3c 와 M-h 를
함께 제거해야 한다.

## 5. 남은 한계 / 후속

**(가) A1 래칫은 기준선 부풀리기를 못 잡는다 — 설계 판단 필요**

**실패하지 않는다.** 래칫이 "줄면 통과하되 경고"로 설계됐기 때문이다.
탐지기를 무력화하는 변경도 같은 경로로 조용히 통과한다(수치가 줄어드는 것으로

의도된 절충이다 — 부채를 고쳤는데 스위트가 빨개지면 아무도 안 고친다. 다만
**"알고 있고 아직 안 고쳤다"는 계약이 소리 없이 깨질 수 있다.** 선택지:

1. 현행 유지 (경고만) — 지금 상태
2. 총합만 정확히 핀 (`sum == 88`), 파일별은 래칫 유지
3. 파일별 정확 일치 강제 — 고칠 때마다 같은 커밋에서 기준선 수정 필수

**추천은 2번이다.** 총합 핀 하나면 탐지기 무력화와 기준선 부풀리기가 둘 다
잡히면서, 개별 파일을 고치는 작업의 마찰은 늘지 않는다. 다만 이번 커밋에는
넣지 않았다 — 래칫 계약 변경은 검토 사항이지 부수 수정이 아니다.

  돌리면 **"신규 우회" 로 실패**한다
- 신 `diag_sell_verdict` 에 구 `diag_fmp_ssot` 를 돌리면 A1 이 `diag_sell_verdict`
  에 대해 "전부 정리됨, 기준선에서 제거할 것" 경고를 낸다(실패는 아님)

건너뛰어도 된다.
