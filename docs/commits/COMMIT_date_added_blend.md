feat(portfolio): 추가 매수 시 보유 기준일(Date_Added) 수량가중 재산정

## 배경
`Date_Added`는 포지션 트레일링 스톱의 **보유 고점 기준일**입니다
(`rc.compute_position_drawdown` · `compute_exit_signals` · `compute_entry_baseline` ·
`fx.hist_days_for_holding`이 모두 이 날짜 하나를 받습니다).
그런데 추가 매수를 해도 최초 매수일이 그대로 보존됐습니다. 눌림에 추가하면 1년 전 고점
기준 -15%가 새 물량에도 적용돼, 사자마자 매도 신호가 뜨는 구조였습니다.

## 결정 (§7 재검토 금지)
- **채택: 수량가중 평균일** — `new = old + (add − old) × q_add / (q_old + q_add)`, 일 단위 반올림
  - 평단가와 같은 계약: 매수 때만 움직이고 매도 때는 그대로
  - 연속적: 소액 DCA는 날짜를 거의 안 움직여 트레일링 기억이 유지됨
  - 역산 가능 → 거래 정정 BUY 롤백에서 복원
  - 스키마 A:F 무변경, regime_core 계약 무변경
- **기각: 추가일 리셋** — 소액 매수 한 번에 트레일링 기억이 소거됨. 매도 신호가 뜬 종목을
  몇 주 사서 경보를 끄는 경로가 생김 (손실 방지 원칙 위반)
- **기각: lot 단위 이원 관리** — G열 추가, legacy 5열 판별, 매도 lot 지정까지 번짐
- 소급 적용 안 함: 기존 날짜는 더 오래된 쪽이라 더 보수적

## 파일별 변경 — app.py (단독)

### 신규 헬퍼 (모듈 레벨, `save_portfolio` 직전)
- `_date_added_ordinal(v)`: 빈 값 / 파싱 불가 / 정상을 구분하고, 시각이 붙은 값은 앞 10자만 봄
- `_blend_date_added(old, old_q, add, add_q)` → `(값, 메시지, applied)`
  - 새 물량 날짜·수량 이상 → 기존 값 유지 + 경고
  - 기존 빈 값 → 새 날짜로 채움
  - 기존 파싱 불가 → 기존 값 유지 + 경고 (조용히 틀리지 않게)
- `_unblend_date_added(cur, Q, lot, q1)`: `d₀ = (Q·D − q₁·d₁) / q₀`. 결과가 오늘 이후이거나 1970 이전이면 기존 값 유지
- `_DATE_BLEND_MEMO_TAG = "[기준일가중]"`: 가중에 **실제로 반영된** 매수의 원장 memo에만 붙음

### 적용 지점
1. **포트폴리오 → 종목 추가 (추가 매수)**: 가중 → 저장. memo 태그, 성공 메시지에 `📅 보유 기준일 X → Y`, 매수일 help 문구 보강
2. **워치리스트 → 매수 등록 (추가 매수)**: 1과 동일
3. **배당 재투자(DRIP)**: 평단을 섞는 매수이므로 같은 규칙 적용. 설계 단계에서 빠졌던 세 번째 경로를 구현 중 발견해 "평단가와 같은 계약" 원칙에 따라 포함함. 소량이라 실질 이동은 거의 없음
4. **🔀 계좌 이동 병합**: `min`(더 오래된 쪽) → 수량가중으로 통일. 병합 전 경고에 예상 기준일 미리보기 추가
5. **🩹 거래 기록 정정 (BUY 취소 + 되돌리기)**: 보유 기준일 역산
   - 역산 대상: memo에 `[기준일가중]` 태그가 있거나 `신규 매수`인 경우
   - 그 외(도입 전 추가 매수·재투자)는 기준일 유지. 날짜에 섞인 적이 없는 lot을 역산하면 기준일이 과거로 밀려 **매수 전 고점에 앵커 → 허위 매도 신호**가 나기 때문
