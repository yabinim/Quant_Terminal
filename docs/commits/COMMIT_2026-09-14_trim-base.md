# feat(portfolio): 트랜치 기준 수량 도입 + 매수/매도 기록 분류 보강

분할 축소 권장량을 **잔여 수량**이 아니라 **고정 기준 수량**의 33%로 계산하도록
바꾼다. 여기에 Thesis 선택지 구멍, 추가 매수 Thesis 유실, 보유 종목 추가 매수
알림 부재, 매도/진입 사유 누락을 함께 정리한다.

배포 순서: `regime_core.py` → `run_watchlist_alerts.py` → `app.py` (3개 lockstep)

---

## 1. 왜 바꾸나

기존 `trim_size_plan()` 은 그때그때의 보유 수량에서 33% 를 뗐다. 그래서 축소를
반복하면 잔여가 0.67ⁿ 으로 줄어들 뿐 **영원히 소진되지 않는다.**

| 회차 | 매도 | 잔여 |
|---|---|---|
| 1 | 33주 | 67주 |
| 2 | 22.1주 | 44.9주 |
| 3 | 14.8주 | 30.1주 |
| 4 | 9.9주 | 20.2주 |

포지션이 끝나는 경로가 🔴 청산 판정과 최소 거래금액 게이트뿐이었고, 실제로
KFY 가 "부분 축소 $18 < 최소 거래 $20" 교착에 빠져 있었다. 기준 수량을 고정하면
3회에 소진되고, 마지막 조각은 정의상 전량이라 `full_exit=True` 가 되어 게이트를
타지 않는다(전량 청산에는 게이트를 걸지 않는다는 기존 규칙 그대로).

**분할 횟수를 저장하지 않는 이유.** 카운터를 컬럼에 두면 앱 렌더와 자동화가
둘 다 증가시킬 수 있어 이중 계상이 난다. 기준 수량 하나만 저장하고 회차는
`(기준 − 현재수량) ÷ 트랜치` 로 파생한다. 권장량과 다르게 매도해도 자동 보정된다.

## 2. 파일별 변경

### regime_core.py (2728 → 2817줄)

**추가: `resolve_trim_base(raw_base, qty)`**
기준은 현재 보유 수량보다 작아질 수 없다는 단일 규칙. 수량이 기준을 넘으면
추가 매수로 보고 새 총량을 새 기준으로 삼는다(= 회차 리셋). 줄어드는 방향으로는
따라가지 않는다 — 따라가면 매도할 때마다 기준이 내려가 영원히 '1번째 축소'가
되고 잔여 기준 계산과 구별이 사라진다. 저장값이 없으면 현재 수량을 기준으로
삼아 종전 동작과 동일하게 첫 트랜치부터 시작한다.

**추가: `trim_base_sync(raw_base, qty)`**
`(적용 기준, 시트에 써야 하는가)` 튜플. 쓰기가 필요한 경우는 저장값 부재와
추가 매수 둘뿐이다. 매도로 줄기만 한 날은 `False`.

**변경: `trim_size_plan()` — `base_qty=` 키워드 추가**
- 포지션 축소 시 `unit = base × tr` 로 계산하고 `n번째 축소 (기준 N주의 33%)` 표시
- 잔량이 `unit × 1.5` 이하면 마지막 조각 → 전량 (부스러기를 남기지 않음)
- 회차 계산에 엡실론 보정: 누적 매도량이 정확히 k·unit 일 때 `//` 가 k−1 을
  돌려주는 부동소수 경계(110.022/55.011 = 1.9999…) 때문에 회차가 하나씩 밀렸다
- 반환 dict 에 `tranche_no`, `base_qty` 추가
- 전량 라벨에 `— 3번째(마지막) 축소` 표기 → '처음부터 전량 청산'과 구분

**스윙 가드.** `swing_weight > 0` 이면 `base_qty` 를 무시하고 잔여 기준 계산으로
되돌린 뒤 note 로 고지한다. 하나의 보유 수량을 두 호흡이 나눠 쓰면, 수량이
줄어도 그게 어느 몫에서 나간 것인지 사후에 알 방법이 없다 — 기준을 세울 수
없으므로 틀린 수량을 확신 있게 말하는 대신 오늘 동작으로 안전하게 되돌아간다.
현재 스윙 몫은 0%(`TRIM_SWING_WEIGHT_FALLBACK_PCT`)이므로 실사용 영향 없음.
호흡별 분리는 스윙을 실제로 쓸 때 별건으로 얹는다.

### run_watchlist_alerts.py (2141 → 2179줄)

- `_PFSTATE_COLS` 에 `Trim_Base_Qty` (H열) 추가, `_PFSTATE_IX_TRIM_BASE = 3`
  (시트 폭은 `_NPF = len(_PFSTATE_COLS)` 파생이라 읽기·병합·패딩·쓰기 범위가
  자동으로 따라온다)
- 보유 루프에서 기준 수량을 해석해 `trim_size_plan(base_qty=...)` 로 전달
- **기준 수량 저장은 쓰기 직전 `_fresh` 병합 이후에 수행.** 병합은 앱에서 고친
  손절/목표를 살리려고 `_row[4:]` 를 통째로 되돌린다. 그 앞에서 H열을 써 두면
  같이 지워진다. `trim_base_sync` 는 순수 함수이자 멱등이므로 최신값 위에서
  다시 적용하는 것이 항상 옳다
- 갱신 발생 시 `[INFO] 트랜치 기준 수량 갱신 N건` 로그

### app.py (28685 → 28819줄)

**스키마 정정 (기존 버그).** `_PORTFOLIO_ALERT_STATE_COLS` 가 6칸이었는데 실제로는
`save_portfolio_swing_weight_setting` 이 G열까지 쓰고 있었다. 헤더 동기화가
A1:F1 만 갱신해 G1 이 이름 없이 남아 있었고, 자동화 정의(7칸)와도 어긋나 있었다.
H열을 추가하면서 8칸으로 맞춘다 — 첫 실행 시 헤더가 A1:H1 로 자가 치유된다.

**추가: `save_portfolio_trim_base_setting()`** — H열만 upsert. 매수 시점에만
호출한다(렌더에서 부르면 rerun 마다 시트 쓰기).

**Thesis 선택지 (`get_thesis_choices`).** 기존 목록은 최근 14일 내러티브에 실제로
등장한 테마만 빈도순으로 뽑았다. 그래서 `_THEME_KEYWORD_MAP` 에 엄연히 있는
`🏦 금융` 이, 2주간 금융 내러티브가 없었다는 이유만으로 선택지에서 사라졌다
(JKHY 매수 시 고를 항목이 없었음). 자동 연결은 내러티브가 그 티커를 추천한 적이
있어야 동작하고 섹터를 보고 추론하지 않으므로 이 구멍을 메우지 못한다.
→ 빈도순 목록 아래 구분선과 함께 **전체 15개 카테고리**를 상시 노출.

**Thesis 라벨 통일.** 포트폴리오 탭 `(Thesis 없음 - 일반 매수)` →
`(Thesis 없음 - 자동 연결 시도)`. 두 경로는 원래 같은 자동 연결을 수행하는데
문구만 달라 "포트폴리오에는 자동 연결이 없다"는 오해를 만들었다. 기능 변경 없음.

**추가 매수 Thesis 유실 수정 (기존 버그).** Thesis 저장 블록이 '신규 매수' 분기
안에만 있어서, 기존 보유 종목에 추가 매수하면 폼에서 Thesis 를 골라도 저장
경로에 도달하지 못하고 **조용히 버려졌다.** `_link_thesis_on_buy()` 로 빼내
신규·추가·워치리스트 세 경로가 같은 코드를 부른다.

**보유 종목 알림에 `entry` 추가.** 종목별 알림 토글 목록이
`["exit","risk","pexit","ptrim","regime"]` 이라 entry 가 아예 없었다. 스윙 몫 0%
계좌의 기본값은 `pexit,ptrim` 이므로 축소 알림만 오고 추가 매수 신호는 한 번도
발동한 적이 없다. 목록에 추가하고 보유 문맥에서는 `🟢 추가 매수 신호` 로 표시한다.
**기본값은 건드리지 않는다** — 켜 둔 토글을 코드가 조용히 바꾸지 않는다는 원칙.

**사유 목록 (둘 다 append-only, 기존 `[진입:]`/`[매도:]` 태그 무영향).**
- 진입 사유에 `⚖️ 리밸런싱` — Robinhood 개인·HSA 계좌는 리밸런싱만 하는데
  선택지가 없어 `📊 정기 적립 (DCA)` 로 기록되고 있었다
- 매도 사유에 `✂️ 줄이기 / 부분 매도 (트랜치)` — 축소를 '매도 신호'로 뭉뚱그리면
  "신호대로 털었는가"와 "계획대로 줄였는가"를 사후에 구분할 수 없다
- 판정이 줄이기면 이 항목을 기본 선택. 판정 분류는 `rc.verdict_action()` 사용
  (부분 문자열 검색 금지 — '청산'은 '분할 청산' 같은 축소 문구 안에도 들어간다)

## 3. 검증 결과

- `py_compile` 3개 파일 전부 통과
- `check_freshness.py` 정합성 9/9 ✅ (regime_core 심볼 41 → 43)
- **역검증(lockstep 트립와이어)**
  - 새 `app.py` + 낡은 `regime_core` → `❌ regime_core: ['resolve_trim_base'] 없음`
  - 새 `run_watchlist_alerts` + 낡은 `regime_core` → `trim_base_sync` 부재

  | 보유 | 권장 |

  | 111.689 | 55.011주 — 2번째 축소 |

  잔여 0.0 · 추가 매수 시 기준 100 → 166.7 리셋 후 다시 1번째부터 확인
- 저장 규칙: `H=''`→쓰기 / `H=100,qty=66.7`→**쓰기 없음** / `H=100,qty=166.7`→쓰기

## 4. 한계 / 후속

- **리밸런싱·현금 확보 매도도 트랜치 진행으로 센다.** 포지션이 실제로 작아진
  것은 사실이므로 의도된 동작이다(사용자 확정). 사유별로 구분하려면 별건.
- **수량이 시트에 반영되어야 동작한다.** 증권사에서 팔고 앱에 기록하지 않으면
  기준도 회차도 움직이지 않는다(기존과 동일한 전제).
- **스윙 몫 > 0 이면 트랜치 기준이 적용되지 않는다.** 호흡별 기준 분리는 별건.
- **추가 매수 시 `Date_Added` 가 보존된다** → 포지션 트레일링 스톱의 보유 고점
  기준일이 최초 매수일 그대로다. 수량가중 평균일 / 신규일 리셋 / 이원 관리 중
  선택이 필요하고 `compute_position_drawdown` 계약을 건드리므로 **별건으로 분리.**
