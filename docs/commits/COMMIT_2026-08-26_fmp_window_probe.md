## 배경

두 개의 미해결 질문이 같은 엔드포인트(`historical-price-eod/full`)를 쓴다.
콜을 합쳐 한 스크립트로 만든다.

1. **`limit` 무시가 확정된 이후 페이로드를 줄일 유일한 후보가 `from`/`to`** 다.
   (인수인계 §3 · §7-B1 최우선). 먹히면 호출부 20여 곳의 페이로드를 한 번에
   줄일 수 있고, 안 먹히면 "줄일 방법 없음"으로 확정하고 타임아웃을 그 전제로
   맞춘다.

2. `Trade_History` 의 GNOM 2026-06-29 매수가 **113.98** 이 산술적으로
   불가능하다(인수인계 §4). Ryan 확인 결과 **실제 체결가는 56.72**.
   0.814×56.72 + 8×56.72 = **$499.93 ≈ $500** 으로 금액 주문 패턴과 일치한다.

## 착수 전 확인한 것 — 가설 하나를 코드로 기각

"어딘가에서 가장 오래된 봉을 집었다"는 가설을 세웠으나, 매수 경로 두 곳을
직접 읽어 **경로가 없음**을 확인했다.

- `app.py:22030` 포트폴리오 매수 폼 — `value=0.0`. prefill 없음. 전량 수동 입력
- `app.py:25077` 관심종목 매수 폼 — `value=current_price`. 유일하게 fetched
  값이 기본값이지만 그건 **당일 현재가**이고, 3차 폴백도 `.iloc[-1]`(최신 봉)

따라서 인수인계 §3 의 "정확성 영향 없음" 판정은 **유지된다**. 그럼에도 프로브
[A] 를 남긴 이유는, 113.98 이 시리즈에 아예 없다는 것을 확인해야 FMP 기원설을
닫고 "수동 입력 오류"로 확정할 수 있기 때문이다. 1콜이다.

**부수 확인**: `diag_industry_momentum.py:208` 이 이미 `from`/`to` 를 쓰고
있으나 아무것도 증명하지 않는다 — 응답을 `{날짜: 종가}` dict 로 담고 별도
날짜 리스트로 조회하므로, 무시돼서 1254봉이 와도 결과가 같다.

### [B] from/to (5콜, SPY)

**날짜 경계로만 판정한다. 봉수·바이트로 판정하지 않는다.**

근거: 봉수는 파라미터가 무시돼도 다른 이유로 달라질 수 있다. 반면 "from 이전
봉이 하나라도 왔다"는 파라미터가 무시됐을 때만 성립한다. (§9 의 "그 값이
맞아야만 성립하는 통계로만 확인할 것" · §6-6 "요청보다 많이 받았다는 한 방향으로
결정적이다")

- `from` 먹힘 = 응답 **최소 날짜 ≥ from**
- `to` 먹힘 = 응답 **최대 날짜 ≤ to**
- **B4(2026-06 창)·B5(2026-08 창) 모두 통과해야 "먹힘" 확정.** 하나만이면
  **불확정** — 한 창의 우연을 배제할 수 없다
- **빈 응답은 "먹힘"이 아니라 "불확정"** — 범위 축소 결과인지 엔드포인트
  장애인지 구분할 수 없다

생기면 자동으로 표에 뜬다.** 변수 limit(`{limit}` 등)은 정적 해석 불가로 표시한다.

## 설계 제약 — 왜 이렇게 만들었나

**원시 `requests.get` 을 쓰지 않는다.** 전부 `fmp_http`(SSOT) 경유.
`diag_fmp_ssot.py` A1 래칫은 기준선에 없는 파일에서 원시 호출이 발견되면
실패한다. 신규 파일은 0곳이어야 한다. → `_RAW_GET_BASELINE` 수정 불필요.

**다른 모듈을 import 하지 않는다.** `run_signal_backtest` 를 빌려 쓰면
gspread·pandas 의존이 딸려오고, 평면 디렉터리에서만 되는 경로 결함이 숨는다
(§6-2). URL 은 여기서 만들고, 호출부 조사는 소스 텍스트로 한다.
의존성은 `requests` 하나뿐이다.

**종료코드 규약**: 파라미터가 무시된다는 결과 자체는 실패가 아니라 **답**이므로
exit 0. 불확정일 때만 exit 2. 프로브가 못 돈 경우(키 없음)만 exit 1.
