# probe(rotation): AUM 필드 실측 프로브 추가 (6콜 · 수동 전용)

## 배경 — 게이트가 아니라 값이 안 온다

2026-09-02, `app.py` 히든알파 버튼에 `rotation_core` 게이트를 연결하자 상위
15개가 **전원** "순자산 미달 · 데이터 없음"으로 떨어졌다. GDX·GDXJ·USO·IBIT·
FBTC·ARKB·SILJ 가 포함돼 있다 — IBIT 는 수백억 달러 규모다.

원인은 필드 이름이다. 코드가 읽는 것은

```python
raw = prof.get("totalAssets") or prof.get("mktCap")   # run_hidden_alpha:389,517
```

이고, 프로젝트 `api-docs.pdf` 의 `/stable/profile` 응답 필드는 **`marketCap`** 이다.

| 키 | 실제 위치 |
|---|---|
| `marketCap` | `/stable/profile` ← **정답 후보** |
| `mktCap` | 레거시 v3. stable 에는 `search-exchange-variants` 에만 남음 |
| `totalAssets` | 재무제표(balance-sheet). profile 에 없음 |

두 키 모두 영원히 안 잡혀 `aum_m` 이 항상 `None` 이 되고,
`passes_aum(None)` 은 설계대로 `False` 이므로 **전원 제외**가 된다.
`rotation_core.py:29` 의 "totalAssets 가 거의 항상 비므로"는 신규 상장 탓으로
봤지만, 실제로는 전 종목이 비어 있었다.

**교차 검증:** GDX 는 유동성 게이트를 **통과하고** AUM 에서 떨어졌다. 거래량·
거래대금 배관은 정상이라는 뜻이고, MSOL $0.87M · TKNS $0.01M 도 실측이 맞다.
결함은 AUM 축 하나에 국한된다.

다음 토요일 5PM 이 첫 실행인데 현재 상태면:

- `compute_actions` 의 `cur_top5` 가 빈 목록 → **지난주 보유 전부가 매도 목록으로**
- 이메일: "신규 매수 해당 없음 + 전량 매도"

## 왜 고치지 않고 재는가

`marketCap` 으로 바꾸는 것이 자명해 보이지만 **ETF 의 marketCap 이 순자산과
같은 수인지는 문서에 없다.** `/stable/etf/info` 에는 `assetsUnderManagement` 가
명시돼 있고 `fmp_extras.fmp_etf_info()` 가 이미 감싸고 있다. 실매매 슬롯을
가르는 게이트이므로 "모르면 안 산다" 원칙대로 재고 고친다.

## 판별자 설계

"필드가 있고 0 이 아니다"는 **판별력이 없다** — 주가도 발행좌수도 상수도 그
조건을 만족한다. 그래서 두 축을 함께 요구한다.

1. **크기** — GDX·IBIT 가 $1,000M 이상인가
2. **분리** — THYP(신규 상장 대조군)가 그 1/100 미만인가

2번이 핵심이다. 세 티커가 비슷한 수를 돌려주면 그 필드는 순자산이 아니다 —
크기 검사만 했으면 통과했을 값이다. `tierB4` 에서 "요청한 날짜부터 왔으니
한도가 3년"으로 잘못 기록했던 것과 같은 실수를 반복하지 않는다.
