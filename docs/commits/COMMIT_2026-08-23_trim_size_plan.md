# feat(portfolio): 트랜치 매도 사이징 — "얼마나 줄여야 하나"에 숫자로 답한다

두 호흡(스윙/포지션) 판정은 이미 독립적으로 계산되고 있었지만 **정보로만**
표시됐다. 사용자는 "🟡 줄이기"를 보고도 얼마를 팔지 스스로 정해야 했다.
보유를 스윙 몫 / 포지션 몫으로 나누고 각 몫에 해당 호흡의 판정을 적용해
권장 매도 수량을 산출한다.

---

## 배경

진입 쪽에는 사이징 게이트(`build_trade_plan` · 리스크 기반 주식 수)가 있는데
매도 쪽은 비어 있었다. `integrated_sell_verdict` 는 점수(200일선 4점 ·
트레일링 3점 · MACD 2점 · 1개월 1점)로 라벨만 내고 수량은 어디에도 없다.

또 하나: 알림 이벤트 기본값 `exit,risk` 는 **스윙 전용**이라, 중장기로만
운용하는 사용자는 🛡 포지션 판정이 스윙 알림에 얹혀서 도착할 때만 볼 수 있었다.
스윙이 조용한 날 포지션이 꺾여도 메일이 오지 않았다.

## 변경 내역

### 1. `regime_core.py` (SSOT · 2393 줄)

`resolve_alert_events` 뒤에 트랜치 블록 신설.

**`resolve_swing_weight(ticker_override, account_default)`**
종목 오버라이드 > 계좌 기본 > `None`. 0~100 클램프.
`None` 과 `0` 을 엄격히 구분한다 — `None` = 기능 미사용(권고 표시 안 함),
`0` = "포지션 100%" 라는 명시적 선택.

**`default_events_for_weight(w, fallback_csv)`**

| 비율 | 반환 |
|---|---|
| `None` | `fallback_csv` (기존 동작 유지) |
| 0 | `pexit,ptrim` |
| 100 | `exit,risk` |
| 그 사이 | `exit,risk,pexit,ptrim` |

명시 저장된 `Alert_States` 는 이 함수를 거치지 않는다. 바뀌는 것은 **'미설정'의
해석뿐**이다. 사용자가 켜 둔 토글을 코드가 조용히 끄면 알림이 사라진 것을
알아챌 방법이 없다.

**`verdict_action(label)`** — 라벨 → `exit`/`trim`/`hold`.

⚠️ **부분 문자열 검색을 쓰지 않는다.** 초안은 `"청산" in label` 이었는데,
매도 어휘에서 '청산' 은 축소 문구 안에도 등장한다(`build_sell_card` 의
headline 이 실제로 "분할 청산·스톱 타이트닝 고려"). 그 라벨이 들어오면 줄이기가
전량 청산으로 분류되어 **보유 전량을 팔라고 권고**한다. 라벨은 항상
`<이모지> <동사>...` 형태이므로 이모지를 떼고 앞머리로 판정한다.
알 수 없는 라벨(`⚪ 판단보류`)은 `hold` — 판정을 못 읽었을 때 매도 수량을
만들어내는 것보다 침묵이 안전하다.

**`trim_size_plan(...)`** — 권장 수량 산출.

    스윙 몫 = qty × w/100 ,  포지션 몫 = qty − 스윙 몫
    청산 → 해당 몫 전량 ,  줄이기 → 해당 몫 × trim_ratio

⚠️ **최소 거래금액 게이트는 부분 축소에만 건다. 전량 청산에는 걸지 않는다.**
$30 짜리 종목이 200일선을 깨는데 "금액 미달로 권고 없음" 이 뜨면 손실 방지의
정반대다. 그리고 게이트에 걸려도 숨기지 않고 "전량 또는 보유 중 선택"으로
전환한다 — 조용히 감추면 사용자는 신호가 없었다고 오해한다.

⚠️ 주식 수를 정수로 반올림하지 않는다. 소수점 주식 보유가 실제로 있다
(AA 0.185주 · AIQ 0.143주).

## 설계 결정 / 기각한 대안

**기각 — 트랜치 실행 추적(`Trim_Done`)**
한쪽 몫을 판 뒤 잔여가 어떻게 갈렸는지 추적하려면 열 2개 + 매도 폼 셀렉트 +
memo 태그가 필요하다. 그런데 **비율이 0 또는 100 이면 몫이 하나뿐이라 추적이
불필요하다**(현재 수량이 곧 그 몫). 중간 비율에서만 의미가 있고, 브로커에서
직접 팔고 기록하지 않으면 상태가 어긋나는 실패 모드가 새로 생긴다.
v1 에서 뺀다. 중간 비율은 "잔여가 설정 비율대로 남아 있다고 가정" 을 UI 와
반환 dict 의 `note` 로 명시 고지한다.

**기각 — `DEFAULT_MIN_TRADE_DOLLARS` 를 0 → 20 으로 변경**
이 상수는 이미 **진입 사이징**을 막고 있다(`regime_core:1167` → `below_min` →
"최소 거래금액 $X 미만"). 전역 기본값을 올리면 매도 기능을 켜려다 게스트 포함
전원의 **매수 동작이 같이 바뀐다**. 상수는 그대로 두고 계좌별로 지정한다.

**채택 — 기존 `Min_Trade_Dollars` 재사용**
"이 금액 미만 주문은 무의미" 라는 개념은 매수·매도가 같다. 별도 임계값을 두면
$50 이하는 못 사는데 $20 어치는 팔라고 하는 모순이 생긴다.

## 남은 한계

- **중간 비율(예 30:70)은 근사치다.** 한쪽 몫만 먼저 판 뒤에도 잔여가 설정
  비율대로 갈려 있다고 가정한다. 0/100 에서는 이 가정이 개입하지 않는다.
- **추가 매수 시 몫 배분을 가정한다** — 새로 산 물량이 기존 비율대로 두 몫에
  나뉜다고 본다. 실제로는 "이번엔 스윙으로만 산다" 가 있을 수 있다.
- **트림폭은 계좌 단위만** — 종목별 오버라이드는 비율(`Swing_Weight_Pct`)에만
  있다. 노브가 두 층으로 갈라지면 값의 출처를 추적하기 어려워진다.
- 이메일의 `_vcolor`(색상)와 `verdict_action`(수량)은 여전히 별도 로직이다.
  색상은 표시일 뿐이라 통합하지 않았다.
