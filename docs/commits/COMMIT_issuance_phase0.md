feat(diag): C트랙 순주식발행 Phase 0 데이터 프로브 — 경로 M/S 판정 + 게이트 12항목

## 왜

C 트랙 다음 후보는 순주식발행이다. 착수 전에 두 가지가 정리됐다.

**① 적용 지점이 바뀌었다.** `SATELLITE_MANDATE.md` §2 를 다시 읽으니 위성 후보 풀은
섹터·테마 ETF 약 60개다. ETF 의 주식 수 변동은 설정/환매 flow 이지 희석이 아니므로
**순주식발행은 위성 룰 후보가 될 수 없다.** 개별 종목 표면 — PEAD 라벨과 같은 모양의
플래그 — 로 간다. 실패의 대가가 문구 한 줄이고, 약정→검증→문구 장치를 재사용할 수
있어서다. 통과하면 그때 스캐너 배제 필터·매도 레이더로 확장한다.

**② 기존 프로브의 B 섹션은 종목 3개짜리였다.** `diag_pead_issuance_probe` 의
B-MCAP 은 AAPL·TSLA·NVDA 에서 "시총÷종가가 시점 기준인가"만 봤다. 횡단면 정렬에
쓰려면 유니버스 규모에서 다시 재야 하고, 그 프로브가 던지지 않은 질문이 하나 있다 —
**두 데이터 경로 중 어느 쪽을 쓸 것인가.**

| | 경로 M 시총÷종가 | 경로 S income-statement |
|---|---|---|
| 빈도 | 일간 | 분기 |
| 지연 | "그날 알 수 있었나"가 불명 → **실측 필요** | filingDate 로 구조적 해결 |
| 재는 양 | 실제 발행주식수 | 가중평균 주식수(평활·희석) |

"3개월 래그"를 추정으로 박지 않고 **계단 발생일 vs filingDate 를 실측해서** 래그
상수를 정하자는 것이 이 프로브의 핵심이다.

## 무엇

### 신규 `automation/diag_issuance_probe.py` (843줄)

읽기 전용 · 1회성. **수익률을 한 줄도 계산하지 않는다** — 종가는 시총의 분모로만
쓰고 두 날짜의 종가 비율은 어디서도 만들지 않는다. 시트 쓰기 0.

판독 기준은 실행 **전에** docstring 에 박았다.

| 게이트 | 재는 것 | 통과 기준 |
|---|---|---|
| I-COVER | 경로별 2012-01-01 이전 도달률 · filingDate 존재율 | ≥80% / ≥90% |
| I-LAG | 계단을 **그 계단이 속한 분기**에 귀속 → filingDate 대비 | 대응률 ≥60% · 필요 래그 ≤120일 |
| I-NOISE | 무변화일 비율 · **무변화 아닌 날**의 중앙 \|Δ\| | ≥50% · ≤0.05% |
| I-ARTIF | 분할로 설명 안 되는 분기 점프(>25%) | ≤2% 종목-분기 |
| I-DISP | 12개월 주식 수 변화율 횡단면(기준일 3개) | 2개 이상에서 IQR ≥2%p · ±3% 밖 ≥15% |
| I-BREADTH · I-COST | 사용 가능 종목 수 · 종목당 콜 수 | 보고 전용 |
| I-PATH | 경로 결정 | 둘 다 자격이면 **M** · 채택 경로 I-DISP ❌ 면 종료 후보 |

두 벌이 되고 나중에 한쪽만 바뀐다 — 대신 **두 파일이 락스텝이 된다.**

## 검증

- `py_compile` 2/2 · `check_py311` ✅ · pyflakes 0건 · 임포트 스모크 ✅
- **셀프테스트 12/12** (합성 세계 · FMP 콜 0)
- **뮤테이션 10 죽음 / 0 생존**

셀프테스트가 실제로 결함 3건을 잡았고, 그중 둘은 설계 결함이었다.

1. **I-LAG 의 분기 접힘(T3).** 처음엔 filing 에서 ±90일 내 가장 가까운 계단을
   골랐다. 계단이 분기마다 서기 때문에 이 방식은 **언제나** 뭔가를 찾아내고, 실제
   200일 지연이 18일로 측정됐다(다음 분기 계단에 걸린 것). 계단을 그 계단이 속한
   분기에 귀속시키는 방식으로 바꿔 접힘을 없앴다.
2. **I-NOISE 중앙값 게이트가 구조적으로 죽어 있었다(M8).** 전체 날의 중앙 \|Δ\| 는
   무변화일이 50% 를 넘으면 자동으로 0 이 된다 — `NOISE_FLAT_MIN` 과 AND 로 묶는
   순간 절대 걸리지 않는 게이트였다. **무변화가 아닌 날**의 중앙값으로 바꿔
   "흔들릴 때 얼마나 흔들리나"를 따로 재게 했다(`NOISE_WIGGLE_MAX`).
3. **분할 가드 창 어긋남(T6).** 분기 인덱스에 합성 월초 날짜를 쓰는 바람에 6월
   중순 분할이 가드 창 밖으로 밀려 '설명되지 않는 점프'로 오분류됐다. 실제
   관측일을 인덱스로 쓰게 고쳤다.

뮤테이션 목록: `I_LAG_MAX_DAYS` · `STEP_MIN` · `NOISE_FLAT_MIN` · `NOISE_WIGGLE_MAX` ·
`ART_JUMP` · `DISP_IQR_MIN` · `DISP_TAIL_MIN` · `LAG_MATCH_MIN` · I-PATH 동률 규칙 반전 ·
분기 인덱스 복귀 — 10건 전부 셀프테스트가 죽였다.

## 한계 · 후속

- 이 프로브는 **경로를 고를 뿐 가설을 검증하지 않는다.** 문턱(P1~P4에 해당하는 것)은
  Phase 1 사전 약정에서 합성 데이터 검정력으로 따로 정한다 — I-DISP 분포를 보고
  정하지 않는다
- 유니버스 크기는 여기서 확정하지 않는다. I-BREADTH 결과 + 검정력 계산으로 약정
  시점에 정한다(PEAD 의 Tier 1 89 + Tier 2 60 은 횡단면 정렬에는 얇다)
- PEAD 판정이 이 티커들의 2012–2021 수익률을 **한 가지 형태로** 이미 봤다. 순발행은
  `PEAD_PRECOMMIT.md` §8 이 말하는 "PEAD 류 질문"과 다른 질문이라 이 구간을 쓸 수
  있다고 보지만, **약정문의 알려진 한계에 명시**해야 할 사항이다
- `SATELLITE_MANDATE.md` 는 이번 커밋에서 건드리지 않았다. §2 후보 풀이 ETF 라는
  사실은 기존 문서에 이미 있고, 순주식발행의 적용 지점 변경은 위성 실험과 무관하다
