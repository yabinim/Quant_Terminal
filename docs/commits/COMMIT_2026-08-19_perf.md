## 제 추측은 네 번 다 틀렸다

이 기록을 남기는 이유는 다음에 같은 실수를 피하기 위해서다.

| # | 추측 | 계측 결과 |
|---|---|---|
| 1 | DRG 계산이 로그인 지연의 원인 | **워치리스트 알림 점검 24.3초(85%)**. DRG 는 무관 |
| 2 | 실적 캘린더는 캐시가 있으니 아닐 것 | **맞았다**(Ryan 짐작). 티커 튜플 전체가 캐시 키라 필터 변경 시 전량 미스 |
| 3 | ETF 자동 갱신은 0.003초, 무죄 | **범인**. 시작 화면에서 건너뛰게 방금 만들어놔서 0.003초였다. 첫 탭 이동 시 profile 60콜 17초 |
| 4 | 병렬화했는데 안 먹으니 FMP 동시성 제한 | **내 `import` 누락**. `_cf` NameError 가 `except` 에 삼켜져 조용히 순차 실행 |

엔드포인트별 집계를 넣고서야 `profile` 60콜이 드러났다.
**총합만 보던 동안에는 '미계측 63콜'이라고만 보였다.**

## 고친 것

### 1. 무거운 작업을 소비 지점으로 이동

원칙: **결과를 쓰는 화면에서만 계산한다.** 이동만으로는 부족했고
(시작 → 첫 탭 → 섹터 탭으로 문제가 옮겨 다녔다), 최종적으로 버튼 게이트가 답이었다.

| 작업 | 전 | 후 |
|---|---|---|
| 워치리스트 알림 점검 (24초) | 로그인 시 | `🔔 Buy Watchlist & Alert` 탭 + 시작 화면 버튼 |
| ETF 유니버스 갱신 (19초) | 첫 탭 이동 시 | 「🔄 신규 ETF 지금 확인」 버튼 |
| 위성 Top10 (34초) | 섹터 탭 진입 시 | 「🛰️ 위성 Top10 계산」 버튼 |
| 실적 레이더 판정 | 탭 진입 시 | 「⚡ 조치 판정 계산」 버튼 |

**알림을 놓치지 않는 3중 장치** — 건너뛸 때 `_watchlist_alert_checked` 를
세우지 않아 다른 탭 이동 시 자동 실행되고, 시작 화면에 즉시 실행 버튼이 있고,
평일 2PM·5PM 이메일이 같은 알림을 보낸다.

### 2. `fetch_latest_prices_for_tickers` 수정 — 두 병목을 한 번에

`batch-quote` 가 **HTTP 402(플랜 제한)** 로 확정됐다. 코드로 못 고친다.

- 배치를 25개 청크로 분할 (한 URL 에 59심볼은 거부될 수 있다)
- 실패 사유를 **화면에 표시** — 로그를 뒤지지 않아도 402 인지 알 수 있다
- 단일 quote 폴백을 **병렬 8워커**로 (`import concurrent.futures as _cf` 누락이 진짜 버그였다)

워치리스트 20초 → 3초, **사이드바 17.7초 → 0초**. 같은 함수라 양쪽이 같이 해결됐다.

### 3. `fetch_earnings_calendar` 종목별 캐시

티커 튜플 전체가 캐시 키였다. 계좌 필터를 하나 켜고 끌 때마다 전량 미스.
종목 단위로 쪼개 **새로 들어온 종목만** 조회한다. 필터를 되돌리면 0콜.

### 4. 계측 인프라 확장

- `_boot_mark` 시작점을 **로그인 직후**로 (메뉴 구성 직전이라 30초 중 4.7초만 잡혔다)
- FMP 호출을 **엔드포인트별 집계** — `by_ep`. URL 쿼리스트링을 잘라 **apikey 유출 방지**
- 계측 누락 구간 보강: 배당 스캔 · 실적 캘린더 · 사이드바 계좌 컨텍스트 ·
  ETF 유니버스 갱신 · 섹터 탭 5구간 · 워치리스트 3구간

### 5. 사용자에게 보이는 개선

- **진행률 바 4곳** — 알림 평가 / 워치리스트 일봉 / 보유 일봉 / 보유 판정.
  8개 미만 루프에는 띄우지 않는다(깜빡임 방지)
- **탭 진입 시 "지난번 N초"** — 2초 이상 걸린 탭에만.
  **"예상 시간"이라고 쓰지 않았다.** 캐시 상태에 따라 몇 배씩 달라지므로
  틀린 예상치는 없느니만 못하다. 측정된 과거값을 과거값으로 제시한다

## 남은 한계

- **`batch-quote` 402 는 못 고친다.** 종목당 약 53ms 라 워치리스트가 100종목을
  넘으면 5~6초가 된다. 그때 다시 본다
- **첫 진입 비용은 구조상 남는다.** 캐시가 비어 있으면 실제로 받아야 한다.
  두 번째부터 빠른 것이 정상이다
- 계측 패널은 **사이드바라 본문보다 먼저 그려진다.** 항상 직전 실행의 숫자를
  보여준다 — Streamlit 렌더 순서라 피할 수 없다.
  측정법: 초기화 → 대상 탭 → 가벼운 탭(시작)으로 이동 → 패널 확인
- `ETF 구성종목 분석` 6.5초는 그대로 뒀다. 사용자가 ETF 를 고른 뒤에 도는
  것이라 기다림이 정당하다
