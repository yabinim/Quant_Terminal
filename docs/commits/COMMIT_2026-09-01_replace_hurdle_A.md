# feat(radar): 슬롯 만석 교체 판정 A단계 — 보유 강도 표시 + 교체 허들 SSOT

> 동반 수정: `position_size` 차단 문구 중복("투자 여유 여유 없음") 해소

포지션 슬롯이 만석일 때 신규 매수 신호가 오면 최약 보유와 교체하는 수밖에 없다.
그동안 시스템은 **"최약 보유와 교체 검토"라는 문구만** 내보내고 누가 최약인지는
알려주지 않았다. 매도 레이더에는 200일선·SPY Alpha·유니버스 랭킹·낙폭만 있어서,
정밀검사 후보의 **강도(0~100)와 같은 자로 비교할 수단이 없었다.**

이번 변경은 그 비교 수단을 만든다(A단계 = 표시). 자동 교체 제안(B단계)은 이
화면으로 "허들이 실제로 몇 번 발동하는가" 데이터를 모은 뒤에 판단한다.

**FMP 추가 호출 0회.** 매도 레이더가 이미 받아둔 400일 종가와 SPY 열을 재사용한다.

---

## 교체 규칙 (두 조건 AND)

| 조건 | 내용 |
|---|---|
| score_ok | 후보 강도 ≥ 최약 보유 강도 + **15** |
| status_ok | 최약 보유가 이미 **매도/경고** 상태 |

**둘 다** 충족할 때만 교체가 성립한다. 한쪽만이면 교체하지 않는다.
허들이 없으면 "신호 올 때마다 갈아타기"가 되어 슬롯 상한이 의미를 잃고
매매 회전율만 오른다.

status_ok 를 요구하는 이유: 그 조건이 참이면 해당 종목은 교체와 무관하게
어차피 정리 대상이다. 즉 규칙은 실질적으로 **"정리할 것을 정리하면서 더 나은
것으로 갈아탄다"** 만 허용한다.

## 파일별 변경

### 1. `regime_core.py` (2,466 → **2,656**)

**신설 — 9-b) 교체 판정 블록 (SSOT)**

| 심볼 | 역할 |
|---|---|
| `REPLACE_SCORE_MARGIN = 15.0` | 요구 마진 |
| `is_weak_status(label)` | 판정 라벨 → 정리대상 여부 |
| `rank_weakest(rows, *, require_full_metrics=True, limit=None)` | 약한 순 정렬 |
| `replacement_hurdle(cand, weak, status, *, margin=…)` | 두 조건 AND 판정 |

**판정 라벨을 상수로 추출** — `VERDICT_SELL` / `VERDICT_TRIM` / `VERDICT_HOLD` /
`VERDICT_WEAK_LABELS`. `integrated_sell_verdict` 가 이 상수를 반환하도록 바꿨다.
**문자열 값은 그대로**이므로 기존 파서·스타일러·시트 기록에 영향이 없다.

왜 상수화했는가: `is_weak_status` 가 **동일성 비교**로 읽게 하기 위해서다.
한글 본문("청산"/"익절")에 substring 검색을 걸면 `"줄이기 (일부 청산)"` 같은
변형을 전량 청산으로 오분류한다 — 과거 같은 방식의 분류기가 정확히 이 케이스에서
틀렸고, 테스트가 그 변형을 담지 않아 전부 통과했다(뮤테이션 테스트에서 발각).
구버전 문자열용 폴백도 문구가 아니라 **선두 이모지**만 본다.

**설계 결정 — "모르면 지목하지 않는다"**

- `is_weak_status` 는 불명 라벨을 `False` 로 돌려준다. 허들은 이 값이 True 여야
  통과하므로, 모르면 교체하지 않는다. 반대로 두면 판정 불명인 종목이 자동으로
  교체 대상이 되어 멀쩡한 보유를 팔게 된다.
- `rank_weakest` 는 강도가 NaN 이거나 `full_metrics=False`(봉 252 미만)인 종목을
  최약 후보에서 **제외**한다. 상장 1년 미만 종목은 52주 창이 짧고 200일선
  기울기가 미수렴이라 다른 종목과 같은 자가 아니다. 제외하지 않으면 신규 상장이
  자동으로 최약이 된다.
- 동점 시 티커 오름차순으로 타이브레이크한다 — 같은 입력이면 항상 같은 최약이
  나와야 화면과 (향후) 이메일이 어긋나지 않는다.

**동반 수정 — `position_size` 차단 문구 (`_SHORTAGE_MSG` + `shortage_message()`)**

`BINDING_LABELS["reserve"] = "투자 여유"` 뒤에 `" 여유 없음"` 을 이어 붙여
**"투자 여유 여유 없음"** 이 나오던 결함을 고쳤다. `risk` → "리스크 기준 여유 없음",
`event` → "이벤트 갭 리스크 여유 없음" 도 어색했다.

두 문구는 쓰임이 다르다 — `BINDING_LABELS` 는 *무엇이 금액을 결정했나*(명사구,
"제한: 투자 여유"), `_SHORTAGE_MSG` 는 *무엇이 없나*(완결 문장). 한쪽을 고치면
다른 쪽이 깨지므로 맵을 분리했다. `BINDING_LABELS` 자체는 손대지 않았다.

소비처 3곳(app.py 정밀검사·워치리스트, 알림 이메일)은 `block_reason` 을 그대로
출력하므로 코드 변경이 필요 없다. 표시 전용 변경이며 사이징 로직에 영향이 없다.

| binding | 이전 | 이후 |
|---|---|---|
| reserve | 투자 여유 **여유** 없음 | 투자 여유 없음 |
| risk | 리스크 기준 여유 없음 | 리스크 예산 없음 |
| event | 이벤트 갭 리스크 여유 없음 | 이벤트 갭 여유 없음 |
| cap | 비중 상한 여유 없음 | 비중 상한 도달 |
| cash | 가용 현금 여유 없음 | 가용 현금 없음 |
| equal | 균등 배분 여유 없음 | 균등 배분 몫 없음 |

### 2. `app.py` (27,839 → **27,999**)

**(a) 매도 레이더 `강도(Score)` 열 신설** — `build_portfolio_sell_radar_df`

- `spy_close_series` 를 호이스트해 `classify_regime` 의 RS 입력으로 재사용
  (이미 받아둔 열이므로 추가 호출 없음)
- `symbol_stats` 에 `score` / `full_metrics` / `bars` 적재
- **숫자형을 유지한다.** 정렬 가능해야 최약을 찾을 수 있다. 봉 부족 표시는
  별표(`42*`)로 값을 문자열화하지 않고 **`판정 근거(Why)` 에 문구로** 붙인다
  → 설계 논의의 ①(정렬)과 ②(봉부족 표시)를 모두 만족시키는 방식
- 내부 플래그 `_score_full` 은 표시 직전 제거

**(b) 계좌별 최약 스냅샷을 `session_state["_pf_weakest"]` 로 발행**

정밀검사 화면이 이 값을 재사용한다. 정밀검사에서 직접 계산하면 보유 종목
히스토리를 다시 받아야 해서 N콜이 붙는다 — 사이드바에 FMP 를 넣었다가
가이드 페이지가 62콜 19.3초 걸렸던 것과 같은 실패 모드다.

**(c) 🛡️ 매도 레이더 → 🎯 매도 판단 상단에 「슬롯 · 최약 보유」 요약**

계좌별로 슬롯 사용량(🟢 여유 / 🟠 만석 / 🔴 초과)과 최약 3종목을 표시한다.
각 행에 **교체 필요 강도**(= 최약 강도 + 15)를 함께 적어 암산을 없앴다.
상한 초과 계좌에는 "교체 이전에 초과분부터 정리하세요" 를 명시한다.

**(d) 정밀검사 사이징 블록에 교체 허들 카드** — `slots_full` 일 때만

`후보 42 vs 최약 38 · 마진 4 < 15 → 명백한 업그레이드가 아닙니다` 형태로
성립/불성립과 두 조건의 충족 여부를 각각 표시한다. 최약 스냅샷이 없으면
(레이더를 아직 안 연 세션) 안내 문구를 낸다.

**사이드바는 손대지 않았다.** 사이드바는 모든 탭에서 그려지므로 여기서 FMP 를
부르면 문서 페이지까지 느려진다(app.py 기존 주석). 만석 문구는 그대로 둔다.

```
                  (봉 120개 종목이 최약 후보에서 정상 제외됨)
```

**뮤테이션 테스트가 실제 결함을 잡았다.** 초안의 `rank_weakest` 는 NaN 가드를
두 번 두었는데(`pd.notna` → `np.isfinite`), 앞의 가드가 죽은 코드라 M8 뮤턴트가
생존했다. **테스트가 아니라 코드를 고쳤다** — 가드를 하나로 합쳤다.
각 뮤턴트는 `py_compile` 로 먼저 검증해 "문법이 깨져서 죽은 것"과 "테스트가
잡아서 죽은 것"을 구별한다.

**역검증 (known-bad 입력에 대해 실패하는가)**

| 입력 | 결과 |
|---|---|
| 구버전 `regime_core.py` + 신 `app.py` | preflight 가 누락 심볼 8개를 지목하고 종료 1 |
