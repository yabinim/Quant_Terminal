# perf(ui): 시작 페이지 신설 + 실적 레이더 지연 계산

로그인 직후 첫 화면까지 10초 이상 걸리던 문제와, 실적 레이더 진입 지연을
각각 다른 방식으로 처리한다.

---

## 1. 시작 페이지 — 착지 지점 이동 + 계측

### 왜 계측을 함께 넣는가

DRG 는 이미 `_drg_get()` 이 스냅샷을 즉시 반환하고 백그라운드로 재계산하는
구조다. 즉 **10초의 주범이 DRG 계산 자체라고 단정할 수 없다.**
원인을 특정하지 않고 페이지만 바꾸면 "다른 페이지도 느림"이 될 뿐이다.

그래서 `_boot_mark()` 로 단계별 소요를 세션에 쌓고, 시작 페이지 하단에
**관리자에게만** 표로 보여준다. 개선 효과를 숫자로 확인할 수 있다.

### 변경

- `_MAIN_NAV_OPTIONS` 에 `"🏠 시작"` 추가 — **반드시 맨 뒤(index 16)**
  중간에 끼우면 `_MAIN_NAV_OPTIONS[n]` 인덱스 분기가 전부 밀려 엉뚱한 페이지가 열린다.
  표시 순서만 `_nav_opts.insert(0, ...)` 로 맨 앞에 배치한다
  (`매매 복기`·`실적 레이더` 가 쓰던 것과 같은 패턴)
- `_render_home()` — **시트만 읽는다.** FMP 호출·가격 이력·DRG 계산 없음
  - 사용 가이드 우선 안내 + 이동 버튼 (요청사항)
  - 개발 리마인더 (관리자, 있을 때만)
  - `ENTRY_BLOCK_DAYS` 내 실적 발표 종목 (캘린더 시트만)
  - 빠른 이동 3개 + 기동 계측 표(관리자)

### `_pv_num`/`_pv_f`/`_pv_money` 모듈 레벨 승격

원래 실적 프리뷰 섹션 안의 **중첩 함수**였다. 지연 게이트(먼저 실행됨)에서
같은 포맷터가 필요해져 모듈 레벨로 올렸다. 그대로 뒀으면 `NameError` 였다.

## 2. 실적 레이더 지연 계산

### 원인

`watch` 분기가 종목마다 `cached_timing_price_history(_tk)` 를 부른다
(ATR 손절 추정). 보유 + 워치리스트 20~30종목이면 탭 진입만으로 수십 초다.
`hold` 분기는 배치 가격 + `evaluate_trim` 이라 상대적으로 가볍다.

### 방식 — 2A + 2C

첫 화면은 **시트만** 읽어 즉시 뜬다.

| 즉시 (시트) | 버튼 후 (계산) |
|---|---|
| 예정 실적 일정 · D-day · 시점 | 차단·축소 판정 |
| 예상 변동폭(과거 중앙값) | 계좌 한도 대비 갭 리스크 |
| 자동화 사전 브리핑 스냅샷 | ATR 손절폭 |

`⚡ 조치 판정 계산` 버튼 → 계산 후 세션 캐시.
캐시 키는 `(사용자, 날짜, 종목집합)` — 종목을 추가하거나 날이 바뀌면 자동 재계산.

### 왜 자동화 사전계산(2B)을 쓰지 않았나

판정은 계좌 프로필과 **수동 손절가**에 의존한다. 사용자가 손절가를 바꿔도
어제 판정이 그대로 뜬다. **낡은 판정은 없는 판정보다 위험하다.**

### 코드 재배치

`_cal = load_earnings_calendar()` 와 `_uni` 구성을 계좌 한도 계산보다
**앞으로** 옮겼다. 게이트가 둘을 참조하는데 원래는 뒤에 있었다
(그대로 삽입했다면 `NameError`).

### 지연 화면이 판정을 사칭하지 않게

"판정은 아직 계산하지 않았습니다" 고지 + 예상 변동폭 옆에
"방향 정보가 아니고, 계좌 한도·손절폭이 반영돼 있지 않다"는 경고를 붙였다.
숫자만 보고 진입 판단을 하면 이 탭의 존재 이유가 무너진다.

## 남은 한계

- **사용 가이드는 이번에 손대지 않았다.** 516줄이라 별건으로 분리했다.
  시작 페이지에서 가이드를 먼저 보라고 안내하므로, 가이드 갱신 전까지는
  낡은 설명을 읽게 된다 — 다음 작업으로 우선순위가 높다
- 기동 계측은 **이번 렌더**만 잰다. 로그인부터 첫 화면까지의 전체 시간이 아니라
  메뉴 구성 이후 구간이다. 이 표에서 10초가 안 보이면 원인이 그 앞
  (인증·세션 복원·`st.cache_data` 콜드 미스)에 있다는 뜻이고, 그때 다시 좁힌다
- 실적 레이더 세션 캐시는 판정 결과가 아니라 **계산 여부 플래그**다.
  같은 세션에서 탭을 다시 열면 재계산한다 — Streamlit 재실행 모델상
  결과 객체를 통째로 캐시하면 손절가 변경이 반영되지 않는다
