**설계 중 코드에서 확인한 것 (문안에 반영)**
- 라이브 `run_earnings_watch.py` 는 `evaluate_pead(m, move)` 로 regime 없이 부른다 → 러너도 같게 부른다
- `move` 가 없으면 `significant=True` 가 되어 모든 반응이 라벨 후보가 된다 → 백테스트 구간 시작에서 체계적으로 생기므로 워밍업 규칙(§4-5)을 넣었다
- `is_candidate` · `is_damage` 는 소비처가 없다. 사용자가 보는 것은 문구뿐이다(`app.py:28147` 표 · 메일 "발표 완료" 블록) → 미달 조치는 `PEAD_LABELS` 문자열 2개 + 플래그. 코드 값은 `Earnings_Events.PEAD_Verdict` 과거 행 호환을 위해 유지
