# feat(portfolio): 계좌 이동 + 거래 기록 정정

계좌를 잘못 골라 등록한 보유를 바로잡을 경로가 없었다. 지금까지는 앱에서
매도 → 재매수로 우회해야 했고, 그 과정에서 **원장에 존재하지 않는 매도·매수
2건이 남아** 실현손익과 매매 복기가 오염됐다.

배포: `app.py` 단독 (regime_core · run_watchlist_alerts 변경 없음)

---

## 1. 왜 지금까지 못 고쳤나

`데이터 수정하기` 는 `(계좌, 티커)` 를 **선택 조건**으로 먼저 고정한 뒤 그 행의
수량·평단가·매수일만 편집한다. 계좌는 편집 대상이 아니라 구조적으로 이동이
불가능했다.

Quant_DB 에서 직접 고치는 것도 안전하지 않다. 계좌·티커로 묶인 저장소가 넷이다.

| 저장소 | 키 | 두고 가면 |
|---|---|---|
| `Portfolios` | Account + Ticker | 보유 자체 |
| `Portfolio_Alert_State` | `uid\|account\|ticker` | 알림 토글·손절·목표가·스윙 비중·트랜치 기준 수량이 옛 계좌에 유령으로 남고 새 계좌는 기본값으로 리셋 |
| `Thesis` | Ticker + Account | 투자 논거가 옛 계좌에 남음 |
| `Trade_History` | account + ticker | **실현손익 FIFO 가 깨짐** — `compute_realized_pnl` 이 `groupby(["ticker","account"])` 로 매칭한다 |

## 2. 추가된 것

### 신규 함수

- **`load_trade_history_indexed(user_id)`** — 시트 행 번호를 달고 로드.
  기존 `load_trade_history` 는 user 필터 후 `reset_index` 를 해서 행 번호가
  사라진다. 그 인덱스로 시트 행을 지우면 **다른 사용자의 거래가 지워진다.**
  캐시도 쓰지 않는다 — 삭제 직전의 실제 행 위치가 필요하다.
- **`delete_trade_history_rows(row_idxs)`** — 반드시 내림차순 삭제.
  오름차순이면 첫 삭제 후 아래 행이 당겨져 두 번째부터 엉뚱한 행이 사라진다.
- **`update_trade_history_account(rows, new_account, tag)`** — B열 갱신 +
  memo 앞에 `[계좌정정: blend→12-0 2026-09-14]`. 과거 원장을 고치는 일이므로
  흔적을 남긴다.
- **`update_thesis_account(...)`** — Thesis C열 이관.
- **`migrate_portfolio_alert_state_key(...)`** — 상태 행의 키를 새 계좌로 rename.
  대상 키가 이미 있으면(합산 이동) **대상 쪽 설정을 살리고** 원본 행을 삭제한다
  — 사용자가 대상 계좌에서 직접 맞춰 둔 손절·목표가를 덮어쓰지 않기 위해서다.
  행 삭제로 인덱스가 당겨지는 것도 보정한다.

### UI A — 🔀 계좌 이동 (포트폴리오 관리)

종목을 다른 계좌로 통째로 이동. 위 4가지가 함께 따라간다. 대상 계좌에 같은
티커가 있으면 합산 결과(수량·가중평균 평단)를 먼저 보여주고 체크박스로 동의를
받는다. 합산 시 `Date_Added` 는 **더 오래된 쪽**을 쓴다 — 트레일링 요구가 깊은
쪽에 맞춰야 매도 신호가 느슨해지지 않는다. 보유가 없는 계좌로도 옮길 수 있다.

**실행 순서: Thesis → 원장 → 알림상태 → Portfolios(마지막).**
앞 단계가 실패하면 보유가 원래 계좌에 그대로 있어 그냥 다시 누르면 된다.
보유를 먼저 옮기면 재시도 시 원본을 못 찾아 복구가 막힌다.

### UI B — 🩹 거래 기록 정정 (전체 거래 내역 위)

잘못 기록한 BUY/SELL 을 원장에서 지우고, 선택 시 포트폴리오를 그 거래 직전
상태로 복원한다.

- **BUY 취소**: `q₀ = Q − q₁`, `p₀ = (Q·P − q₁·p₁) / q₀`
  (검증: 20주@$150 + 실수 5주@$180 = 25주@$156 → 취소 → 20주@$150 완전 복원)
  `q₀ ≤ 0` 이면 포지션 제거, 음수면 수량을 건드리지 않고 경고.
- **SELL 취소**: `q₀ = Q + q₁`, 평단가 유지(매도는 평단을 바꾸지 않는다).
  전량 매도로 행이 사라진 경우는 **평단가와 매수일을 직접 입력받는다** —
  추정해서 채우면 트레일링 스톱 기준일이 조용히 틀어진다.
- **체크박스를 끄면 기록만 삭제** — 이미 손으로 수량을 맞춰 둔 경우용.

**실행 순서: 원장 삭제 → 포트폴리오 복원.**
반대로 하면 삭제 실패 시 재시도에서 같은 거래가 두 번 되돌려져 수량이 더 줄어든다.
이 순서는 최악이라도 '기록은 지워졌는데 수량이 그대로'라 `데이터 수정하기` 에서
손으로 바로잡을 수 있다.

**시트 읽기는 '최근 거래 불러오기' 버튼 뒤에 둔다.** expander 는 접혀 있어도
본문이 실행되므로, 무조건 읽으면 포트폴리오 탭 rerun 마다 Trade_History 를 조회한다.

### 트랜치 기준 수량 — 명시적 예외

매수 취소로 수량이 줄면 기준을 **복원 수량까지 내린다.** "기준은 내려가지
않는다"(`resolve_trim_base`)의 유일한 예외다.

부풀려진 기준을 두면 `q ≤ unit × 1.5` 조건에 걸려 다음 줄이기 신호에서 곧장
"전량 매도 — 마지막 축소"가 뜬다(기준 166.7 / 실보유 66.7 → unit 55). 잘못된
청산 권고는 손실 방지 원칙 정면 위반이므로 선택지가 아니다.

## 4. 한계 / 후속

- **계좌 이동은 전량 이동만 지원.** 한 종목의 일부만 다른 계좌로 쪼개는 건
  '거래 정정으로 취소 → 올바른 계좌에 재기록' 2단계로 처리한다. UI 에도 안내.
- **부분 실패 시 자동 롤백 없음.** 단계별 결과를 메시지로 그대로 보여주므로
  어디까지 됐는지 확인하고 재실행하면 된다(순서가 재시도 안전하게 잡혀 있다).
- 추가 매수 시 `Date_Added` 재산정은 여전히 별건으로 남아 있다.
