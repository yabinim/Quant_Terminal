# fix(diag): dividend-adjusted 가격 필드 자동 선택 — 조용히 실패하던 0-D/0-E 복구

`diag_sell_verdict.py` 단일 파일. 2026-08-27 첫 실행(NEE) 로그에서 드러난 결함을
고치고, 그 결함을 잡는 회귀 케이스 2건을 `[T]` 에 추가한다.

`diag_fmp_ssot.py` 는 **변경 없다** (44/44 유지 확인).

---

## 1. 실행이 알려준 것

첫 실행은 exit 0 이었고 `[S]` `[T]` `[3]` 전부 초록이었다. 그럼에도 **`[0]` 블록은
자기 목적을 달성하지 못했다.** 로그가 스스로 모순을 드러냈다:

```
0-C: limit=600 호출  → kind=ok, 1254행
     from/to 460일   → kind=ok,  316행
0-D: dividend-adjusted → 응답 없음        ← 1,254행을 받아놓고 "응답 없음"
0-E: ⚠️ 비교 대상 소스가 하나도 안 나왔다
```

### 확정된 사실 (가설 3개 기각)

| 가설 | 실측 | 판정 |
|---|---|---|
| 중복 날짜가 MA200 을 끌어내린다 | 1254행 / 고유 1254 → 중복 **0건** | 기각 |
| 200봉 창이 어긋나 있다 | 2025-11-10~2026-08-27, **290일** (기대 290) | 기각 |
| 봉이 부족하다 | **1,254봉** 확보 | 기각 |

즉 **87.87 은 미조정 종가의 정직한 200봉 단순평균이다.** 계산 자체는 맞다.
외부 89.77 / 91.64 와의 격차는 계산 오류가 아니라 **정의 차이**로 좁혀졌고,
그 마지막 후보(배당조정)를 재보려면 아래 결함을 먼저 고쳐야 했다.

### 부수 확인

- `limit=600` 을 요청했는데 **1,254행**이 왔다 — §7 의 "`limit` 무효" 재확인이자,
  동시에 **`dividend-adjusted` 가 현재 플랜에서 완전히 사용 가능**하다는 뜻이다.
- `historical-price-eod/full` 응답에 **`adjClose` 가 없다**
  (change, changePercent, close, date, high, low, open, symbol, volume, vwap).
  따라서 같은 엔드포인트 안에서의 조정/미조정 대조는 이 플랜에서 불가능하다.

## 2. 결함 — 필드명을 하드코딩했다

`block0` 이 `_hist_from_rows(alt, "close")` 로 `close` 를 고정해 읽었다.
`dividend-adjusted` 는 `adjClose` 로 온다. `_hist_from_rows` 는 요청한 필드가
없으면 **빈 DataFrame** 을 돌려주고, `_ma200_row` 는 그것을 `"응답 없음"` 으로
출력한다 — **네트워크 실패와 스키마 불일치가 화면에서 똑같이 보였다.**

같은 레포의 `diag_satellite_backtest.py:226` 이 이미 정답을 알고 있었다:

```python
col = "adjClose" if "adjClose" in df.columns else "close"
```

레포에 실증된 사실이 있는데도 새 코드에서 다시 틀렸다. 그래서 이번엔
**헬퍼로 뽑아 한 곳에 둔다**(`_price_field`).

### 왜 `[T]` 9케이스가 못 잡았나

스텁 `_t_stub` 이 `dividend-adjusted` 응답을 만들 때 `_t_rows(n, adj=False)` 를
썼다 — 즉 **항상 `close` 가 있는 응답**만 먹였다. 현실에 없는 스키마를 고정한
픽스처였고, 그래서 초록불이 났다.

추가로 T1 픽스처는 `div_lim=100 < div_win=330` 으로 **실측과 정반대 세계**를
고정하고 있었다(실측은 1254 > 316). 그 때문에 "짧은 쪽 시리즈를 고른다"는
두 번째 결함도 함께 통과했다.

## 3. 변경 내역 (`automation/diag_sell_verdict.py` 974 → 1057줄)

**(가) `_price_field(rows, prefer=("adjClose","close"))` 신설**
행에 실제로 존재하는 가격 필드를 고르고, 없으면 `None`. 판정 규칙을 한 곳에
모아 다음에 또 다른 경로에서 같은 실수를 반복하지 않게 한다.

**(나) 0-C — 더 긴 시리즈를 쓴다**
기존 `alt = alt_win or alt_lim` 은 1,254행을 버리고 316행을 골랐다.
`alt = alt_lim if n_lim >= n_win else alt_win` 으로 바꿨다.

**(다) 0-C — 서술을 실측에 맞춘다**
기존 문구는 "`limit` 이 무시되고 기본 창이 **짧았다**" 였다. 실제로는 `limit` 이
무시되면 **전체가 온다.** 방향이 반대였다. 이제 `n_lim`/`n_win` 대소에 따라
갈라 쓰고, **어느 호출을 채택했는지와 받은 필드 목록**을 함께 출력한다.

**(라) 0-D — 필드 자동 선택 + '가격 필드 없음'을 '응답 없음'과 분리**
행이 왔는데 쓸 필드가 없으면 받은 필드 목록을 그대로 보여준다. 다음 사람이
로그만 보고 원인을 알 수 있어야 한다.

**(마) `[T]` 9 → 11 케이스**
- `_t_rows(with_close=False)` · `_t_stub(div_schema=...)` 추가 —
  **`adjClose` 만 오는 실제 스키마**를 재현할 수 있게 했다. 기본값을
  `"adjClose"` 로 둔 것은 그것이 실측된 모양이기 때문이다.
- **T8**: `dividend-adjusted` 가 `adjClose` 로만 옴 → `"응답 없음"` 이 나오면 실패.
  이번 결함 그 자체를 고정한다.
- **T9**: 가격 필드가 정말 없는 응답 → 받은 필드 목록이 출력돼야 한다.
- **T1 픽스처를 실측 비율로 교체** (`div_lim=600 > div_win=316`) 하고,
  채택된 시리즈(`limit 경로 600행`)까지 문자열로 고정했다.

## 5. 남은 한계 · 후속

- **배당조정 가설은 아직 미판정이다.** 이번 수정으로 다음 실행에서 처음으로
  실제 비교가 이뤄진다. 사전 예측은 "배당조정 MA200 ≤ 미조정" 이며, 그렇다면
  외부값이 더 높은 것을 배당조정으로는 설명할 수 없다는 결론이 확정된다.
  **결과를 보고 기준을 바꾸지 않는다.**
- `run_watchlist_alerts._fmp_price_history` 의 dedupe 누락은 **여전히 미수정**
  이다. 이번 실측에서 NEE 중복이 0건이라 87.87 의 원인은 아니었지만, 다른
  종목에서 같은 보장이 없다. 라이브 5PM 경로 수정이라 별도 커밋으로 다룬다.
- 같은 함수의 `limit=252` 도 그대로다(실제로는 1,254봉 수신).
- `/full` 에 `adjClose` 가 없으므로 `has_adj` 분기는 이 플랜에서 사실상 죽은
  경로다. 다만 플랜/스키마가 바뀔 수 있어 제거하지 않고 남긴다.
