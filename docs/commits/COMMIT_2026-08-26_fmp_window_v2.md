## 핵심 설계 — 기준선 시리즈를 정답지로 쓴다

v1 은 경계만 봤다. v2 는 **B1(무파라미터) 응답을 먼저 받아 그 시리즈에서 창 안의
봉 수를 직접 세어 기대값**으로 삼는다.

**추가 콜 0회로 판정력이 올라간다** — 기대값이 외부 가정이 아니라 같은
엔드포인트의 실측이기 때문이다. (§9 "파라미터가 먹혔는지는 그 값이 맞아야만
성립하는 통계로만 확인할 것")

### 사전 확정 판정 기준 (결과 보기 전 파일에 못 박음)

| 조건 | 판정 |
|---|---|
| 경계 위반 (from 이전 / to 이후 봉 존재) | `ignored` |
| 경계 OK · 실제 == 기대 (±1봉) | `honored_complete` |
| 경계 OK · 실제 < 기대 | `honored_truncated` — 넓은 창에 쓸 수 없다 |
| 경계 OK · 실제 > 기대 | `anomaly` |
| 빈 응답 | `inconclusive` |

±1봉 허용 근거: 기준선과 창 요청 사이 수 초에 당일 봉이 생길 수 있다.
**2봉 이상은 허용하지 않는다.**

**최종 "전환 가능" = B2~B5 · D1 · D2 가 전부 `honored_complete`.**
하나라도 truncated 면 전환 불가.

### [D] 완전성 (신규 2콜)

- **D1 중간폭**: `from` = 기준선 중앙 날짜 (약 600봉대)
- **D2 전폭**: `from` = 기준선 최초 날짜 (약 1254봉)

D2 가 complete 여야 `run_signal_backtest` 처럼 최대 깊이가 필요한 곳도
전환할 수 있다.

### [E] 하류 소요 봉수 감사 (신규 0콜)

**⚠️ 이 감사가 존재하는 이유 — `limit` 은 한 번도 강제된 적이 없다.**

현재 호출부의 `limit` 값들은 전부 무의미했다. 뭘 적든 1254봉이 왔다. 즉 그
숫자는 "필요한 최소 봉수"가 아니라 **"누가 언젠가 적어둔 값"** 이고 한 번도
검증된 적이 없다. `from` 으로 전환하는 순간 그 숫자가 **처음으로 실제 상한이
된다.**

AST 로 호출부 파일의 긴 윈도우 신호를 찾는다: `rolling(N)` · `ewm(span=N)` ·
`.tail(N)` · `.iloc[-N:]` · `*_BARS/LOOKBACK/WINDOW/PERIOD/MIN_PRIOR* = N`.
`limit < 관측최대N` 이면 **위험**.

단위 환산도 추정하지 않는다. `limit` 은 거래일, `from` 은 달력일이므로
**기준선 응답에서 거래일/달력일 비율을 실측**해 권고 오프셋을 낸다
(안전계수 1.10 + 고정 여유 10일).

**드라이런 결과(제 사본 기준, 21곳): 안전 1 · 위험 9 · 판정보류 11.**
순진한 `limit → from` 전환이 위험하다는 것이 수치로 나왔다.

## 작성 중 잡힌 결함 3건 — 기록

**1. S16·S18 의 기대값이 틀렸다.** `COUNT_TOL=1` 인데 "2봉 중 1봉 부족"을
truncated 로 기대했다. 실제로는 complete 다. → S16 을 2봉 부족으로 고치고,
±1봉 통과를 확인하는 S18·S18b 를 분리 신설했다.

**2. N6 가 뮤테이션을 통과했다 — 판별 케이스가 없었다.**
S30 의 `PORT = 8080` 은 이름 필터가 아니라 **크기 필터(`_CONST_MAX=5000`)에
먼저 걸려** 탈락한다. 이름 필터를 통째로 제거해도 결과가 같다. §6-1
("None 을 기대하는 테스트는 잘못된 이유로도 통과한다")의 재현이다.
→ 5000 미만이면서 이름이 봉수와 무관한 상수(`MAX_WORKERS = 8`,
`TIMEOUT_SEC = 20`)를 넣어 S30b·S30c 를 신설. N6 가 잡힌다.

**3. 삼항 연산자 안에 `1/ratio` 가 있었다.** ratio=0 이면 조건이 먼저
평가되어 실제로는 안 터지지만, 읽는 사람이 판단할 수 없는 코드다.
평범한 `if` 로 풀었다.

## 인수인계 문서 오류 정정 (§4 관련)

`Trade_History` GNOM 을 56.72 로 고친 뒤 `diag_trade_history` 를 돌린 결과,
**HSA Fidelity 계좌 통계가 −14.45% 에서 전혀 움직이지 않았다** (N=7 동일).

원인: 해당 표는 **「개별 매도만」** 인데 GNOM 두 행은 `리밸 Y`(리밸런싱 매도)라
**애초에 그 표에 없었다.** 인수인계 §4 의 "이 2행을 빼면 +0.7%" 는 다른 표의
숫자를 갖다 붙인 것이고, 그것을 이어받아 계산한 −0.68% · −0.11% 도 전부 무효다.

GNOM 수정의 실제 효과는 **리밸런싱 매도(69건) 쪽 통계에만** 반영된다.
(§6-8 "인수인계 문서의 진단도 틀릴 수 있다 — 착수 전에 실제 코드를 직접 확인할 것")

**추가 정정**: 이전 세션에서 제기한 "`diag_trade_history` 평균이 롯 등가중"
결함 주장은 **틀렸다.** `금액가중%` 열이 이미 존재한다(HSA: 평균 −14.45 vs
금액가중 −14.66).
