## 0. 함께 고친 기존 결함 — 미수신 메일이 안 나갔다

`dispatch_radar_emails` 최상단에 이 가드가 있었다:

    total = 발동 건수 합계
    if not total:
        print("[INFO] 발동/활성 건 없음 — 이메일 생략.")
        return

`main()` 은 `if total or nodata_total():` 로 제대로 호출하는데, **함수에 들어오자마자
잘렸다.** 즉 **발동 0건 + 미수신 있음** 인 날의 메일이 한 번도 나가지 않았다.

`diag_nodata_radar.py` 의 첫 문단이 경계하던 바로 그 실패다 —
*"미수신을 기록해도 발송 게이트가 걸러 버리는 경우 … 침묵을 알리는 메일이 같은
이유로 침묵한다."* 그런데 **92/92 통과 상태로 놓쳤다.**

이유는 검사 방식이다. 기존 스위트는 `_send_one_user` 의 가중치 계산과 main 의
조건식을 **AST 로** 봤다. AST 는 '무엇을 호출하는가'는 보지만 **함수 안의 조기
반환 조건식은 못 본다.** 그래서 이번에 `dispatch_radar_emails` 를 **실제로
실행하는** 검사(G군)를 추가했고, 기존 코드에 물리면 G-1 이 즉시 실패한다.

    구 가드로 역검증 → G-1 ❌(sent=0) · G-2 ❌ · 통과 114 · 실패 3

**교훈: 계약(AST) 검사는 배선을 보증하지 그 안의 판단을 보증하지 않는다.**

## 1. A-2c 는 무엇인가

A-2a/A-2b 는 **데이터가 빈 뒤에** 움직인다. 상장폐지 종목이 이력을 며칠 더
흘려보내면 그동안 매도 신호는 오지 않는데 경고도 없다. A-2c 는 그 앞에 선다 —
미수신을 기다리지 않고 워치리스트·보유 전체를 **주 1회** 대조한다.

### 판정은 한 방향뿐이다

    ∈ actively-trading-list  →  거래 중 확정. 아무것도 안 한다
    ∉ actively-trading-list  →  **아무것도 단정하지 않는다.**
                                profile 로 다시 물어 '사망/소멸'만 알린다

부재를 사망으로 읽으면 안 되는 이유: 그 리스트에 점(`.`) 포함 심볼이 **0종**이라
해외 표기가 통째로 빠져 있고, 소형주·OTC 커버리지는 아직 미검증이다. 부재만으로
딱지를 붙이면 **정상 보유 종목에 사망 경고**가 간다. 원인을 모르는 것보다 틀린
원인을 붙이는 게 나쁘다(A-2b 와 같은 원칙).

근거는 2026-08-22 `membership2` 실측이다: 26,252종 · `BBBY`(사망)·`BNRG`(사망)
둘 다 부재 · `AAPL`·ETF 5/5 존재 → 양방향 확인. **단 '미국 보통주 + 주요 ETF'
범위 안에서만이다.**

### 비용

    월~목      0콜 (요일 게이트)
    금요일     1콜(목록) + K콜(부재분만 profile). K 는 평소 0, 상한 25
    시트       금요일에만 2회 추가 읽기

`LIVENESS_FORCE=1` 로 요일 무시 수동 실행(`run_weekly_report` 의 `_FORCE_RUN` 패턴).

### 오탐 방어 4겹

| 가드 | 막는 것 |
|---|---|
| 목록 조회 실패 → `None` 반환 | 빈 집합을 '전 종목 부재'로 읽는 것 |
| `_LIVENESS_MIN_UNIVERSE = 5000` | 잘린 응답이 온 날 전 보유에 사망 경고 |
| `_LIVENESS_ABSENT_RATIO = 0.30` | 커버리지 구멍(해외·OTC)을 떼죽음으로 오독 |
| `_LIVENESS_MIN_SAMPLE = 10` | **비율 게이트가 작은 표본에서 진짜 상폐를 삼키는 것** |

앞의 두 개는 **의도적으로 중복**이다. 목록 조회가 빈 집합을 돌려줘도 하한선이
막는다. 하나만 남기면 그 하나가 틀렸을 때 잡을 게 없다 — 주석과 회귀 양쪽에
못을 박았다(`F2` 군이 조회 계약을, `F-3` 이 하한선을 각각 고정).

네 번째는 이번에 회귀가 잡아준 것이다. 초판은 비율 게이트에 표본 하한이 없어서
**2종목 중 1종목이 죽으면 50% 라며 경고를 삼켰다.** A-2a 의 `_NODATA_MIN_SAMPLE=5`
와 같은 이유로 하한을 뒀다.

  작동하지 않는다. 이건 설계상 감수한 것이지 결함이 아니다.
