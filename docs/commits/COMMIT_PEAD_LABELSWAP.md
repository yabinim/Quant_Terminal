## 변경 — `earnings_core.py` (2444줄)

### 1. `PEAD_LABELS` 문구 2개
```
"up_continue": "🟢 상승 지속 후보"      → "🟢 강한 상승 반응"
"down_break":  "🔴 하락 이탈 — 근거 훼손" → "🔴 강한 하락 반응"
```
- **코드 값은 불변.** `Earnings_Events.PEAD_Verdict` 의 과거 행이 그대로 읽히고,
  앱 표는 코드 → `PEAD_LABELS` 로 그리므로 과거 행도 새 문구로 다시 보인다
- 나머지 4개(`up_faded` · `down_recovered` · `muted` · `na`)는 원래 관찰 문구라 불변
- 딕셔너리 위에 **근거 주석 블록**을 붙였다: 수치 · 문턱 · 왜 바꿨는지 ·
  "옛 문구로 되돌리려면 §8 대로 새 사전 약정을 먼저 써야 한다"

### 2. `evaluate_pead` 플래그
- `"is_candidate": True` · `"is_damage": True` 대입 제거 → **항상 False**
- 키는 남긴다(호출부 호환). docstring 에 이유와 복구 조건을 적었다
- 현재 두 플래그를 읽는 곳은 저장소에 없다 — 표시·메일 모두 `label` 만 쓴다

### 3. 레짐 약세 분기 문구
```
"단 레짐 약세 — 진입 근거로는 부족"  →  "레짐 약세"
```
옛 문구는 **이 판정이 진입 근거였다는 전제**를 깔고 있었다. 판정이 미달했으니
전제부터 없앤다. 분기 자체(약세면 사유를 덧붙이고 조기 반환)는 그대로 둔다.

## 변경 — `app.py` (28592줄)

실적 레이더 "발표 완료" 표 아래 캡션(1곳). 옛 문구를 그대로 쓰고 있었고,
"하락 이탈은 … 기존 근거 훼손 신호로만 씁니다" 라는 **미달한 주장**을 담고 있었다.
판정 수치와 "이후 방향을 말하지 않는다"는 사실로 교체했다.

메일(`run_earnings_watch.py`)도 `pead["label"]` 을 그대로 쓰므로 무변경이다.
